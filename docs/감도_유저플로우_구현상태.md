# 감도(GAMDO) 사용자 플로우 구현 상태

> **문서 상태: 대체됨.** 2026-07-29 이후의 전체 기능·구현·P1 연결·GPU 배치 상태는
> `docs/감도_전체기능_구현상태_2026-07-29.md`를 기준으로 확인한다. 아래 내용은 이전 구현
> 이력 보존용이며, FLUX·IC-Light·ViewCrafter·영역 선택·12종 프레임 이전 상태를 포함한다.

> 문서 기준일: 2026-07-25  
> 기준 브랜치: `main` / 활성 P2 브랜치 `codex/p2-plan-sync`  
> 목적: 계획서의 기능 목록과 실제 앱에서 사용자가 수행할 수 있는 동작을 분리해 기록한다.  
> 우선순위: `AGENTS.md`의 확정 결정과 현재 코드·실기기 검증 결과를 우선한다.

## 상태 표기

- **실행 가능**: 현재 APK에서 사용자가 해당 동작을 끝까지 수행할 수 있음.
- **부분 연결**: 코드·서버·데이터 일부는 있으나 일반 사용자 플로우가 완전히 연결되지 않았거나 검증 범위가 제한됨.
- **계획/미구현**: 계획서에는 있으나 현재 앱 화면에서 사용자가 수행할 수 없음.
- **후순위**: 외부 사진·라이선스·실기기 입력·추가 모델이 필요하거나 프로토타입 범위 밖이라 현재 진행하지 않음.

## 1. 현재 실행 가능한 사용자 플로우

### 1.1 최초 실행과 권한

1. 앱 최초 실행.
2. 카메라·사진 접근 권한 안내 확인.
3. 권한 허용 요청.
4. 권한을 거부한 뒤 재요청.
5. 다시 묻지 않음 상태에서 Android 설정 화면 열기.
6. 설정에서 권한을 허용하고 앱으로 복귀.
7. 권한이 없으면 카메라·사진 기능 대신 안내 화면에 머무름.

### 1.2 온보딩과 취향 저장

1. 취향 카드 화면 진입.
2. 카드 선택·해제.
3. 선택값 0개로 시작.
4. 최소 3장 선택.
5. 3장 미만이면 다음 버튼 비활성화.
6. 선택 완료 후 감도 저장 화면 진입.
7. 촬영 시작하기 선택.
8. 선택한 카드 ID를 로컬에 저장.
9. 선택 결과에 따라 추천 프리셋 ID 저장.
10. 온보딩 완료 상태 저장.
11. 앱 재실행 시 온보딩을 건너뛰고 카메라로 직행.

현재 번들 카드 메타데이터는 16개다. 실제 고유 이미지 수와 카드 출처·라이선스는 별도 확인이 필요하다. 저장 화면의 요약 문구와 색상 설명은 선택 결과에 따라 동적으로 생성되지 않고 고정 문구다.

### 1.3 카메라 촬영

1. 카메라 프리뷰 확인.
2. 얼굴·포즈 감지 상태 확인.
3. 얼굴 박스·인물 중심점·수평선 오버레이 확인.
4. 목표 프레임·실루엣 가이드 확인.
5. 기기 기울기에 따른 수평선 변화 확인.
6. 4:5와 1:1 화면 비율 전환.
7. 두 손가락 핀치로 연속 줌.
8. 현재 배율을 0.1x 단위로 확인.
9. 전면·후면 카메라 전환.
10. 셔터로 사진 촬영. **실기기에서 새 캡처 파일 생성과 오류 로그 미발생 확인(2026-07-25).**
11. 앱 전용 저장소에 원본 저장.
12. `Pictures/감도`에 갤러리 내보내기.
13. 촬영 직후 최근 사진 썸네일 확인.
14. 썸네일을 눌러 앨범 진입.
15. 상태 칩을 눌러 개발용 HUD 표시·숨김.

서버 업로드는 자동으로 발생하지 않는다. 사진 살리기를 명시적으로 실행할 때만 업로드한다. 일반 사용자용 6종 스타일 순환 UI는 없고, 온보딩에서 정해진 추천 프리셋이 기본 적용된다. Debug 빌드에서는 개발용 프리셋 표시를 눌러 프리셋을 순환할 수 있다.

### 1.4 앨범과 갤러리 가져오기

1. 카메라에서 앨범 진입.
2. 촬영 사진을 3열 그리드로 확인.
3. 썸네일을 눌러 보정 화면 진입.
4. 앨범의 가져오기 선택.
5. Android Photo Picker에서 사진 선택.
6. 선택 사진을 앱 전용 저장소로 복사.
7. `gallery_import` 출처로 로컬 DB에 기록.
8. 가져온 사진을 앨범 목록에서 확인.
9. 가져온 사진을 눌러 보정 화면 진입.
10. 뒤로 가기로 카메라 복귀.

앨범이 비어 있으면 빈 상태 안내를 표시한다.

### 1.5 로컬 보정과 저장

1. 선택 사진을 보정 화면에서 확인.
2. 로컬 보정 중에도 원본을 먼저 확인.
3. 다음 필터를 선택.
   - 원본
   - 내 감도
   - 따뜻한 카페
   - 밝은 리뷰
   - 소프트 필름
   - 야간 거리
4. 밝기 슬라이더 조절.
5. 따뜻함 슬라이더 조절.
6. 대비 슬라이더 조절.
7. 조정 결과 미리보기 확인.
8. 원본을 유지한 채 편집 결과 생성.
9. 편집 결과와 파라미터를 로컬 DB에 기록.
10. 결과를 갤러리에 저장.
11. 같은 사진을 반복 저장.
12. 앨범으로 돌아가기.

### 1.6 사진 진단

사진 상태에 따라 다음 자연어 진단 칩을 볼 수 있다.

- 조금 어두워요
- 빛이 강해요
- 선명도를 확인해보세요
- 기울기를 확인해보세요
- 여백이 넓어요
- 뒤에서 빛이 들어와요

역광 입력 경로는 카메라 Y 평면의 전체·얼굴·배경 밝기 샘플링까지 연결되어 있다. 실제 역광 장면에서의 임계값 적합성은 미검증이다.

### 1.7 사진 살리기와 GPU 생성 복구

1. 보정 화면에서 사진 위를 드래그.
2. 지울 영역을 직사각형으로 선택.
3. 선택 영역 확인.
4. 사진 살리기 실행.
5. 선택 영역을 정규화 마스크로 변환.
6. `POST /api/v1/edit-jobs` 요청.
7. 작업 상태 폴링.
8. CAMP-2의 FastAPI → worker → ComfyUI → LaMa → InsightFace 처리.
9. 검증 통과 결과 다운로드.
10. 최대 2개 생성 후보 확인.
11. 후보 선택.
12. 선택 후보를 현재 결과로 적용.
13. 후보를 로컬에 기록.
14. 갤러리에 저장.

다음 경우에는 오류를 그대로 노출하지 않고 기본 보정 결과로 폴백한다.

- 네트워크 실패
- ComfyUI 미준비
- InsightFace 검증 실패
- 작업 실패
- 결과 다운로드 실패
- 얼굴 보호 마스크에 의한 생성 차단

상태 폴링은 구현되어 있으나 `queued`, `processing`, `validating`을 상세히 표시하거나 작업을 취소하는 UI는 없다.

## 3. 계획서에는 있으나 현재 사용자가 수행할 수 없는 플로우

### 3.1 소개·개인정보

- 서비스 소개 화면 확인.
- 핵심 가치 확인.
- 서버 전송 시점과 원본 삭제 정책 확인.
- 온디바이스 처리와 서버 처리 구분 확인.

### 3.2 완성형 온보딩

- 15~20개의 고유 카드 탐색.
- 8개 취향 축을 균형 있게 커버하는 카드 선택.
- 실제 출처·라이선스가 확인된 카드 사용.
- 선택 카드에서 동적 프로필 생성.
- 선택 결과 기반 자연어 요약 확인.
- 추천 스타일 3개 확인.
- 서로 다른 선택에 따른 추천 순서 변화 확인.

### 3.3 스타일 시스템

- 스타일 강도 0~100% 조절.
- 6종 스타일 직접 선택.
- 스타일 탐색 화면과 컬렉션 탐색.
- 개인 프리셋 이름 지정·저장·목록·삭제.
- 두 스타일 혼합.
- 스타일 프로필 화면.
- 개인화 초기화.

### 3.4 고급 장면 인식과 구도 제안

- 장면 스캔.
- 리딩 라인·개방 공간·배경 복잡도 분석.
- 문·창·기둥 등 일반 객체 감지.
- 음식·건물·풍경·제품 장면 분류.
- 구도 후보 2~3개 생성.
- 좌우 스와이프 후보 변경.
- 재스캔.
- 장면 변화에 따른 자동 재제안.
- 다중 인물 추적과 주 피사체 선택.
- 인물·배경 분할 및 겹침 분석.

### 3.5 레퍼런스 따라 찍기

1. 카메라에서 레퍼런스 진입.
2. Photo Picker에서 레퍼런스 선택.
3. 업로드 전 개인정보 안내 확인.
4. 사진 해시 계산과 캐시 조회.
5. 필요 시 `/references/analyze` 업로드.
6. 분석 결과 로컬 캐시.
7. 분석 목표 구도를 카메라 오버레이에 적용.
8. 레퍼런스 원본 반투명 오버레이.
9. 투명도 0~60% 조절.
10. 원본 오버레이와 실루엣 오버레이 전환.
11. 레퍼런스 색감 적용.
12. 레퍼런스와 결과 나란히 비교.
13. 촬영·저장.

현재 앱에 레퍼런스 진입 화면이 없어 전체 흐름은 실행할 수 없다.

- 발표용 영상·백업 APK 준비.

## 4. 대표 데모 기준

현재 실기기에서 수행 가능한 대표 흐름은 다음 두 가지다.

1. `온보딩 → 카메라 가이드 → 촬영 → 앨범 → 필터·슬라이더 보정 → 저장`
2. `앨범 가져오기 → 사진 선택 → 영역 드래그 → GPU 객체 제거 → 후보 선택 → 저장`

레퍼런스 따라 찍기, 고급 장면 제안, 피드백 기반 재개인화, 결과 비교 탭, 공유·되돌리기, 자동 마스크·아웃페인팅은 계획 상태이며 현재 APK에서 수행할 수 없다.

## 5. 검증·외부 의존 항목

다음은 코드만으로 완료 판정하지 않는다.

- 두 손가락 핀치 줌의 실제 손가락 판정.
- 오버레이 인물 정렬·색 전환 최종 육안 판정.
- 실제 역광 사진의 임계값 판정.
- 실제 인물 사진 기반 InsightFace 임계값 캘리브레이션.
- 큐레이션 사진 품질 판정.
- 카드 이미지 출처·라이선스 확인.
- 일반 Wi-Fi·핫스팟 환경 리허설.
- 발표 장소 조명에서 시나리오 A·B 반복 리허설.

외부 사진·라이선스·추가 모델이 필요한 항목은 별도 승인 전까지 후순위로 둔다.
