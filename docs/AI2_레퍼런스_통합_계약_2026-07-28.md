# AI 2 레퍼런스 분석·내 감도 통합 계약

작성일: 2026-07-28  
담당: P2 분석·저장·적용 로직 / P1 화면 연결

## 범위

사용자가 사진 한 장을 선택하면 CAMP-2가 구도와 색감을 분석하고, 결과를 로컬의 단일 `내 레퍼런스` 슬롯으로 저장한다. 시스템 프리셋 6종은 유지한다. 사진 살리기·생성 편집은 이 문서의 범위가 아니다.

최상위 데모 컷 결정 중 AI 2 관련 항목만 부활시킨다. P1 소유 Compose·디자인 파일은 P1이 연결한다.

## 사용자 흐름

```text
사진으로 만들기 → Photo Picker → CAMP-2 전송 안내 → 캐시 확인
→ CAMP-2 분석 → 적용 범위 선택 → 내 레퍼런스 활성화
→ 촬영 구도·촬영 후 색감에 적용
```

적용 범위는 `BOTH`, `COMPOSITION`, `COLOR` 세 가지다. 기본값은 `BOTH`, 강도 기본값은 `0.7`이다.

## API 계약

- `POST /api/v1/references/analyze`
- `X-Device-Id` 필수
- JPEG·PNG·WebP, 최대 20MB·24MP
- 폐쇄형 데모 서버는 원본·정규화본·분석 중간 산출물을 품질 디버깅용으로 보관할 수 있다. 자동 삭제는 요구사항이 아니며, 정리는 수동 데모 정리 시 수행한다.
- 응답 `analysisVersion=3`.
- `targetComposition.layoutSlots`는 최대 4개이며 좌표는 정규화된 `[x, y, width, height]`다.
- 구도 분석이 불가능하면 `capabilities.composition=false`로 반환하고 임의 구도를 생성하지 않는다.
- 색감 분석은 구도 분석 실패와 독립적으로 성공할 수 있다.

## 앱 저장·수명

- `cached_references.content_hash`는 원본 바이트 SHA-256이다.
- `analysis_v=3` 캐시는 동일 사진 재선택 시 네트워크를 호출하지 않는다.
- 이전 분석 버전은 같은 사진을 다시 선택했을 때 한 번 갱신한다.
- 활성 레퍼런스는 `app_settings`의 hash·scope·strength로 기록한다.
- 비활성 캐시는 최대 20개·30일이다.
- 앱·서버의 정규화본과 업로드 임시 파일은 분석 재현·디버깅을 위해 데모 작업 기간 보관할 수 있다.
- 네트워크 실패 재시도 횟수와 보관 기간은 품질 테스트에 맞춰 제한 없이 조정할 수 있다.
- 원본 오버레이 파일은 사용자가 레퍼런스를 교체·삭제하거나 앱 데이터를 초기화할 때까지 로컬에 보관할 수 있다.

`EXIF` 제거는 적용 가능한 경우 수행하되, 제거 실패가 분석·적용 흐름을 막아서는 안 된다. 전체 정책은 `감도_데모_데이터_운영계약_2026-07-28.md`를 따른다.

## 구도·색감 적용

`ReferenceScope.COLOR`는 구도 가이드를 만들지 않는다. `BOTH`와 `COMPOSITION`은 서버의 `layoutSlots`를 `LayoutTemplate`으로 변환해 `LayoutSource.REFERENCE`로 즉시 고정한다. 레이아웃은 현재 카메라 물체를 추적하지 않는다.

색감은 `ColorTarget → ColorParams → LocalEditor`로 연결하고 원본을 덮어쓰지 않는다. 레퍼런스 우선순위는 `레퍼런스 → 세션 프리셋 → 온보딩 추천`이다.

## P1 연결 요구사항

- 스타일 스트립의 `+ 사진으로 만들기`
- 업로드 목적·삭제 고지
- 분석 상태·구도/색감 미리보기
- `구도와 색감 / 구도만 / 색감만` 선택
- 6종 뒤 `내 레퍼런스` 슬롯
- 교체·삭제
- 현재 세션의 원본 반투명 오버레이(기본 30%, 0~60%)
- 결과 화면의 `내 레퍼런스` 색감 항목

기술 신뢰도·색온도·카메라 높이·점수는 제품 UI에 표시하지 않는다.
