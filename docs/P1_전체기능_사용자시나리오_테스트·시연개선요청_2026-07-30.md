# 감도 전체 사용자 시나리오·기능 검증 및 시연 개선 요청

작성일: 2026-07-30  
대상: P1 (화면·Compose·카메라 UX·결과 화면 통합 담당)  
목적: 현재 감도에 구현된 기능을 사용자 흐름 순서로 빠짐없이 정리하고, P1이 이를 바탕으로 **UI/UX 개선안**과 **시연·성능 개선안**을 제안·연결할 수 있게 한다.

## 1. P1에게 요청하는 산출물

아래 모든 시나리오를 기준으로, 각 기능을 `사용자에게 보이는 화면`, `누를 버튼/제스처`, `진행·실패 상태`, `결과 확인·저장`까지 빠짐없이 점검해 달라.

각 항목에 대해 다음 두 관점의 개선안을 별도로 작성해 달라.

1. **UI/UX 관점**: 진입점, 정보 우선순위, 버튼 명칭·위치, 로딩·실패 상태, 비교·저장 흐름, 처음 보는 사용자가 이해할 수 있는지.
2. **성능·시연 관점**: 첫 화면 표시, 카메라 프리뷰·가이드 반응, 긴 GPU 작업의 진행 상태, 실패 시 복구, 데모에서 반드시 성공해야 하는 최소 경로.

P1은 순수 디자인 판단을 자유롭게 제안할 수 있다. 다만 아래 `P1 연결 필요`라고 적은 버튼·제스처·상태는 기능을 사용 가능하게 만들기 위한 필수 연결이므로 누락하지 않는다. P2의 탐지·서버·생성 로직을 화면에서 직접 재구현하지 않고 공개 Controller/StateFlow 계약을 소비한다.

## 2. 상태 표기

| 표기 | 뜻 |
|---|---|
| 사용 가능 | 현재 앱에서 진입·실행 가능한 경로 |
| 코어 구현 | P2 로직/서버는 있으나 P1 화면 연결 또는 최신 실기기 확인이 남음 |
| 제한/결함 | 기능은 보이거나 진입되지만 현재 사용자 흐름을 완료로 볼 수 없음 |
| 후순위 | 데모에는 포함될 수 있으나 현재 기본 시연 경로가 아님 |

## 3. 전체 사용자 여정

```text
앱 최초 실행
→ 취향 카드로 기본 감도 생성
→ 카메라에서 자동 구도 또는 수동/영역 구도 선택
→ 사용자가 직접 촬영
→ 앨범에서 사진 선택
→ 현재 감도 또는 시스템 필터로 로컬 보정·저장
→ 필요 시 사진으로 내 감도 만들기
→ 필요 시 AI로 사진 살리기
→ 결과 비교·새 파일 저장

선택 확장:
내 감도를 친구에게 QR로 전달
→ 친구 웹 카메라에서 같은 고정 가이드로 촬영
→ 내 앱에서 사진 수신·현재 감도 적용
```

라이브 카메라 프레임은 서버로 업로드하지 않는다. 서버/GPU는 사용자가 레퍼런스 사진 분석 또는 AI 생성 보정을 명시적으로 실행할 때만 사용한다.

## 4. 시나리오 A — 최초 실행과 기본 감도 만들기

### A-1. 온보딩 진입

```text
앱 첫 실행
→ 카메라/사진 권한 확인
→ 취향 카드 선택
→ 5장 이상 선택
→ 내 감도 저장
→ 카메라로 진입
```

| 기능 | 현재 상태 | 사용자가 경험해야 하는 결과 | P1 점검/개선 요청 |
|---|---|---|---|
| 권한 요청 | 사용 가능 | 권한 허용 후 바로 온보딩 또는 카메라 진입 | 거부/재시도/설정 이동이 과도하게 막지 않는지 |
| 취향 카드 | 사용 가능 | 처음에는 선택 0개, 5장 이상에서 저장 가능 | 카드 선택 상태, 최소 선택 안내, 저장 CTA의 명확성 |
| 시스템 감도 6종 추천 | 사용 가능 | Clean Social, Candid Feed, Bright Review, Soft Film, Casual Portrait, Night Street 우선순위가 저장됨 | 사용자는 기술 점수 없이 추천 결과를 이해할 수 있어야 함 |
| 상황별 감도 프로필 V2 | 코어 구현 | 전역 선호와 야간 인물·카페 음식·전신 등 상황별 정책을 로컬 저장 | 현재 UI에 상황별 정교화 진입이 부족함. 과도한 설정 화면 없이 제안 |
| 적응형 카드 추가 묶음 | 코어 구현 | 12장 → 12장 → 선택적 최대 8장, 총 최대 32장 | P1 카드 데이터·선택 진행 UI 필요 |
| 좋아하는 사진 최대 20장으로 감도 정교화 | 코어 구현 | 사용자가 사진을 골라 기존 프로필을 더 정교하게 만듦 | 다중 선택, 진행 상태, 완료 후 어떤 변화가 생기는지 사용자 언어로 제안 |

### A-2. 기본 감도의 의미

- 기본 감도는 단순한 필터 이름이 아니라 촬영 가이드 우선순위와 촬영 후 기본 색감의 출발점이다.
- 현재 프로필에는 줌 선호, 피사체 비중, 여백, 기울기, 카메라 높이 선호, 인물 프레이밍 성향, 색감이 포함될 수 있다.
- 사용자는 숫자·신뢰도·모델 용어를 보지 않는다. P1은 이를 한두 문장의 사람 언어 요약 또는 자연스러운 기본 동작으로 표현하는 방안을 제안한다.

## 5. 시나리오 B — 카메라에서 구도 잡고 촬영

### B-1. 카메라 기본 동작

```text
카메라 진입
→ 기본 자동 탐색
→ 장면이 안정되면 고정 구도 가이드 표시
→ 사용자가 카메라/피사체를 직접 움직여 맞춤
→ 셔터
→ 사진 저장·앨범 진입
```

| 기능 | 현재 상태 | 사용자에게 보여야 하는 동작 | P1 점검/개선 요청 |
|---|---|---|---|
| 풀블리드 카메라 | 부분 연결 | 화면 여백 없이 실제 카메라처럼 프리뷰가 중심 | 상단 4:5/1:1 칩 제거, 프리뷰·저장 좌표 일치 |
| 촬영·저장 | 사용 가능 | 셔터는 언제나 누를 수 있고 MediaStore에 새 사진 저장 | 셔터 후 앨범 진입·복귀가 자연스러운지 |
| 앨범 진입 | 사용 가능 | 촬영 직후 결과 또는 앨범으로 이동 | 촬영 결과가 어디에 저장됐고 다음 행동이 무엇인지 명확성 |
| 줌·탭 포커스·전후면 전환 | 사용 가능 | 일반 카메라 조작처럼 동작 | 과도한 HUD/실험용 버튼을 최종 데모 화면에서 숨길지 판단 |
| 수평선/기울기 | 사용 가능 | 시각 수평선만 표시 가능 | 텍스트 지시·점수·화살표·자동 촬영은 금지 |
| 탐색 로딩 | 코어 구현 | 탐색 중 작고 비텍스트 로딩, 확정 뒤 사라짐 | 눈에 거슬리지 않는 위치·표현 제안 |

### B-2. 자동 장면 인식 구도

```text
카메라가 화면 중앙·하단의 주요 객체를 탐색
→ 유효 객체 1~4개를 3/5 새 검출로 안정화
→ 사진 구도 템플릿 선택
→ 객체마다 목표 슬롯 하나를 고정 표시
→ 사용자가 대상 배치를 맞춰 촬영
```

| 기능 | 현재 상태 | 동작 계약 | 현재 실기기 이슈/점검 |
|---|---|---|---|
| EfficientDet 객체 탐지 | 제한/결함 | 라벨이 없어도 유효 객체는 후보가 됨 | 자동 인식률, 작은/흩어진 객체, 객체 수 분리 정확도가 낮음 |
| 객체 1:1 목표 슬롯 | 코어 구현 | 선택된 객체 1개당 슬롯 1개, 최대 4개 | 검출기가 붙은 물체를 하나의 박스로 내면 하나로 처리됨 |
| 중복 억제·프레임 간 추적 | 코어 구현 | 같은 물체 중복 슬롯 억제, 확정 뒤 이동하지 않음 | 인접·겹친 물체에서 중복/합침 재검증 필요 |
| 기본 구도 라이브러리 | 코어 구현 | 단일/삼분할, 2개 균형·대각, 3개 삼각, 4개 다이아몬드·주보조 등 | 실제 사진으로 찍었을 때 유용한지 UX·시연 평가 필요 |
| 배경·케이블·가장자리 억제 | 코어 구현 | 모니터/노트북/케이블은 주 피사체로 세지 않음 | 책상·교실 장면에서 오인식 재검증 |
| 확정 고정 | 사용 가능 | 재탐색 전까지 슬롯이 피사체를 따라다니지 않음 | 사용자가 고정/재탐색 상태를 이해할 수 있게 표현 |
| 성능 | 제한/결함 | 목표: 첫 가이드 2초, 평균 8 FPS, drop 20% 이하 | SM-S928N에서 CPU 폴백, drop이 18~30%로 흔들림 |

### B-3. 탭 재탐색

```text
사용자가 피사체 근처를 탭
→ 해당 지점 주변으로 자동 탐색 초기화
→ 안정 장면 확정
→ 새 고정 가이드
```

- 탭은 한 객체를 강제 선택하는 기능이 아니라, 탭 주변의 피사체 그룹을 다시 찾는 기능이다.
- P1은 탭 포커스 성공 직후 `rescanAt()` 계열 공개 API를 호출해야 한다.
- 점수/인식 라벨을 사용자에게 노출하지 않는다.

### B-4. 영역 선택(올가미)

```text
영역 선택 버튼
→ 선택 모드 활성화
→ 사용자가 물체들을 한 번에 감싸 드래그
→ 경로 자동 닫힘
→ 영역 내부 객체를 ROI로 재탐색·안정화
→ 객체별 고정 슬롯
→ 취소 또는 재탐색
```

| 기능 | 현재 상태 | 동작 계약 | 현재 실기기 이슈/점검 |
|---|---|---|---|
| 영역 선택 모드 API | 코어 구현 | 상시 드래그가 아니라 전용 버튼 후에만 동작 | P1 버튼·경로 수집·완료·취소 연결 필요 |
| 다각형 좌표 변환 | 코어 구현 | 풀블리드 프리뷰 경로를 분석 좌표로 변환 | 전후면·회전·레터박스 상황 확인 |
| 영역 유효성 | 코어 구현 | 2% 미만 또는 80% 초과 영역은 무효 | 무효 시 사용자가 이해 가능한 피드백 필요 |
| 영역 내부 객체만 선택 | 수정 반영·재검증 필요 | 객체 박스의 50% 이상이 내부일 때 후보, 밖 객체 제외 | **현재 실기기에서 하나만 인식되는 결함이 보고되어 앵커 클러스터 제거 수정 적용 후 재검증 필요** |
| 다중 객체 확정 | 수정 반영·재검증 필요 | 내부 독립 객체를 최대 4개 각각 슬롯으로, 3회 ROI 관찰 후 고정 | 3개 이상 물체·경계 물체·밖 바로 옆 물체 반복 확인 필요 |
| 겹친 물체 분리 | 제한 | 탐지기가 하나의 박스만 반환하면 임의 분리하지 않음 | 별도 YOLO instance segmentation 후속 후보 |

### B-5. 수동 프레임

```text
프레임 버튼
→ 하단 프레임 패널
→ 12종 중 하나 선택
→ 인식 여부와 무관하게 즉시 고정 가이드
→ 촬영 또는 자동 재탐색으로 복귀
```

현재 P2는 12종 카탈로그와 `availableManualLayouts`, `selectManualLayout()`을 제공한다. P1의 프레임 버튼·하단 패널 연결이 필요하다.

| 범주 | 수동 프레임 |
|---|---|
| 인물 | 전신 중앙, 전신 삼분할/비대칭, 걷는 순간·리드 룸, 상반신, 앉은 인물 |
| 객체 | 단일 중앙, 단일 삼분할, 2개 균형, 2개 대각, 3개 삼각, 주 피사체+보조 |

수동 선택은 현재 세션에서만 유지하며, 카메라를 나갔다 들어오면 기본 자동 탐색으로 돌아간다.

### B-6. 인물 가이드

| 기능 | 현재 상태 | 사용자 경험 |
|---|---|---|
| 얼굴 + person 박스 기반 인물 판단 | 코어 구현 | 전신/상반신/환경 인물 프레임을 안전하게 선택 |
| 인물 브래킷/실루엣 | 코어 구현, P1 렌더링 필요 | 사람이 맞출 고정 윤곽만 보여줌 |
| 인물 + 객체 | 코어 구현 | 인물 1개 + 객체 최대 3개를 동시에 슬롯으로 표시 |
| 포즈 점·막대 | 폐기 | 관절 추론·점수·정렬 판정은 사용하지 않음 |

P1은 `PERSON_BRACKET`/실루엣을 흰색 반투명 고정 가이드로 렌더링해야 한다. 얼굴·관절 박스, 일치 점수, 채움 색상 변화, 행동 지시 문구는 최종 화면에 표시하지 않는다.

### B-7. 촬영 화면의 감도·필터

| 기능 | 현재 상태 | 사용자 경험 | P1 점검/개선 요청 |
|---|---|---|---|
| 시스템 감도 6종 | 사용 가능 | 스타일 선택 | 하단 필터가 항상 노출되지 않고 필터 버튼 후 패널로 나타나야 함 |
| 내 감도 | 사용 가능/재검증 필요 | 활성 레퍼런스 또는 프로필 기반 선택 | 선택 상태·기본 적용이 명확한지 |
| 사진으로 내 감도 만들기 | 사용 가능 | 필터 패널의 `+`에서 진입 | 카메라·결과 화면 공통 진입 UX |
| 레퍼런스 원본 오버레이 | 사용 가능 | 현재 세션의 레퍼런스 사진을 0~60% 투명도로 겹쳐 구도 참고 | 투명도 버튼이 의미를 전달하도록 디자인 개선 |
| 카메라 프리뷰 색감 | 제한/연결 확인 필요 | 필터 선택 시 촬영 전 색감 미리보기 | 실제 GL/LUT 렌더 경로와 폴백·기기별 안정성 검증 |

## 6. 시나리오 C — 사진으로 내 감도 만들기(AI 2)

```text
카메라 또는 결과 화면의 + 내 필터 만들기
→ 시스템 Photo Picker
→ 서버 분석·삭제/보관 고지
→ 분석 중
→ 팔레트·4:5/1:1 구도 미리보기
→ 구도와 색감 / 구도만 / 색감만 선택
→ 내 감도 적용
→ 카메라 가이드 및 결과 색감에 반영
```

| 단계 | 현재 상태 | 사용자가 확인해야 하는 결과 | 현재 이슈/개선 요청 |
|---|---|---|---|
| 사진 선택 | 사용 가능 | JPEG/PNG/WebP 한 장 선택 | 진입 위치가 필터 패널에서 자연스러운지 |
| 업로드 고지 | 사용 가능 | 사용자가 명시적으로 분석 동의 | 문구는 짧고 목적 중심이어야 함 |
| 분석/캐시 | 사용 가능 | 같은 사진 재선택은 캐시 사용, 구버전 캐시는 갱신 | 진행 중 이탈·오류·재시도 UX |
| CAMP-2 분석 | 서버 사용 가능 | 주요 피사체/구도/팔레트/명암/색감 파라미터 반환 | 분석 품질은 사진군 실측 미완료 |
| 범위 선택 | 사용 가능 | 구도+색감, 구도만, 색감만 | 사용자가 차이를 이해하도록 미리보기 필요 |
| 내 감도 활성 슬롯 | 사용 가능 | 시스템 6종을 대체하지 않는 단일 슬롯 | 교체/삭제/앱 재시작 복원 UX |
| 레퍼런스 구도 | 코어 구현 | 현재 장면 자동 구도보다 우선하는 고정 가이드 | 카메라 UI에서 적용 여부 확인 필요 |
| 레퍼런스 색감 | 제한/결함 | 촬영 후 결과에서 참고 사진 분위기가 반영됨 | **현재 실기기에서 지나치게 쨍한 결과만 보이며 레퍼런스 분위기 재현이 부족함** |
| 필터 목록 유지 | 제한/결함 | 내 감도를 선택해도 6종 + 내 감도 목록이 사라지지 않음 | **실기기에서 목록 소실 재발 보고. ResultFilterStateHolder 단일 원천 연결/렌더 실패 폴백 확인 필요** |

### C-1. 내 감도 색감의 기대 경험

사용자는 레퍼런스 사진을 "색을 더 세게 만드는 필터"로 기대하지 않는다. 예를 들어 따뜻한 역광·어두운 실루엣·낮은 대비·필름 질감 사진을 선택했다면, 다음 사진에서도 색온도, 밝은 영역 보존, 그림자, 대비, 채도, fade, grain, vignette가 함께 참고되었다고 느껴야 한다.

P1은 다음을 점검해 달라.

- 참고 이미지·원본·내 감도 결과를 어떻게 비교하면 과포화/과대비를 즉시 발견할 수 있는가.
- 내 감도 적용 후 필터 패널과 사진이 사라지지 않도록 어떤 상태 분리가 필요한가.
- 색감 실패 시에도 기본 6종 필터와 원본이 항상 남는 UX가 되는가.

## 7. 시나리오 D — 촬영 후 앨범·로컬 보정·저장

```text
촬영 후 결과 또는 앨범
→ 앱 촬영본과 기기 사진이 섞인 그리드
→ 사진 선택
→ 현재 감도 기본 결과 / 원본 / 시스템 필터 비교
→ 밝기·따뜻함·대비 조절 또는 필터 선택
→ 새 파일 저장
```

| 기능 | 현재 상태 | 사용자 경험 | P1 점검/개선 요청 |
|---|---|---|---|
| 단일 앨범 그리드 | 사용 가능 | 앱 촬영 사진과 기기 사진을 시간순으로 함께 봄 | 앱 사진/기기 사진의 보정 차이를 사용자가 이해하는지 |
| 앱 촬영본 자동 기본 보정 | 사용 가능 | 촬영 환경을 바탕으로 수평·광학·스타일 출발점 적용 가능 | 결과 진입 시 어떤 필터가 기본인지 명확성 |
| 기기 사진 원본 진입 | 사용 가능 | 사용자가 고르지 않은 자동 보정은 하지 않음 | 원본과 필터 적용 상태가 혼동되지 않는지 |
| 시스템 필터 6종 | 사용 가능 | 필터 선택 후 로컬 비파괴 렌더 | 하단 스트립/필터 팝업과 선택 상태 |
| 현재 내 감도 기본값 | 코어 구현, P1 연결 필요 | 우선순위: 활성 레퍼런스 색감 → 촬영 세션 스타일 → 온보딩 추천 → 원본 | `recommendedDefaultFilterId`를 실제 ResultScreen이 소비해야 함 |
| 기본 수동 보정 | 사용 가능 | 밝기, 따뜻함, 대비 등의 로컬 조정 | 필터와 수동 조정의 관계·되돌리기·저장 UX |
| 전체 해상도 새 파일 저장 | 사용 가능 | 원본을 덮어쓰지 않고 새 결과 저장 | 저장 완료/실패/갤러리 반영 피드백 |
| 고급 편집/전후 비교 | 부분 구현 | `ResultEditController`, `LocalEditor`, 비교 슬라이더 경로 존재 | 현재 `QuickFilterEditor` 중심 화면과 통합할지 P1 판단 필요 |

### D-1. 반드시 테스트할 결함

1. 사진 업로드 후 내 감도를 만든다.
2. 앨범 사진을 연다.
3. 내 감도 필터를 선택한다.
4. 사진·필터 스트립이 유지되는지, 실제 색감 렌더가 되는지 확인한다.
5. 다른 필터·원본으로 이동한 뒤 다시 내 감도로 돌아오는지 확인한다.
6. 앱 재시작 후에도 활성 내 감도와 필터 목록이 복원되는지 확인한다.

## 8. 시나리오 E — AI로 사진 살리기(AI 3)

### E-1. 현재 진입과 공통 흐름

```text
앨범에서 사진 선택
→ AI로 보정
→ CAMP-2 사진 진단
→ 추천 또는 직접 수정 선택
→ 작업 파라미터 확인
→ 실행 버튼
→ queued / processing / validating 폴링
→ 원본·현재 감도·AI 후보 비교
→ 하나 선택해 새 파일 저장
```

앱 촬영 사진과 일반 기기 앨범 사진 모두 대상이다. 추천을 보기만 해서는 업로드·edit-job이 생기지 않고, 사용자가 실행을 눌러야 생성이 시작된다.

| 기능 | 현재 상태 | 사용자 경험 | 현재 이슈/개선 요청 |
|---|---|---|---|
| 사진 진단 | 사용 가능/재검증 필요 | 현재 감도와 사진 상태를 바탕으로 최대 3개 제안 | AI 보정 진입 뒤 무엇을 해야 하는지 불명확하다는 실기기 보고 |
| 내 감도로 정리하기 | 제한/결함 | 서버 job 없이 즉시 로컬 색감 결과로 전환 | **실기기에서 선택해도 아무 변화가 보이지 않음. 결과 선택/렌더/상태 표시 연결 점검 필요** |
| 기억 보존(MEMORY) | 코어 구현 | 로컬 색감·밝기·수평·가벼운 크롭만 | 재해석 수준 선택 UI 필요 |
| 감도 적용(GAMDO) | 코어 구현 | 감도 정책에 맞는 생성 작업 추천 | 추천·직접 편집·실행 구분 UI 필요 |
| 다시 찍었다면(REIMAGINE) | 코어 구현 | 더 적극적인 시점/화각 재해석 후보 추천 | 과도한 생성 약속 없이 범위 설명 필요 |
| 결과 후보 비교 | 제한/연결 확인 필요 | 원본·기본 보정·AI 후보를 비교 후 저장 | 후보 도착/다운로드/선택 UI와 긴 대기 상태가 불편함 |
| 실패 폴백 | 코어 구현 | 생성 실패 시 원본·기본 보정은 유지 | 실패가 무음으로 사라지지 않게 표현 |

### E-2. AI 작업별 사용자 시나리오

| 작업 | 사용자가 선택할 의도 | 가능한 선택값 | 서버/GPU 상태 | P1 점검/개선 요청 |
|---|---|---|---|---|
| 내 감도로 정리 | 현재 취향의 로컬 보정만 적용 | 별도 생성 없음 | Android LocalEditor | 실행 즉시 전후 변화·저장 가능해야 함 |
| 방해 요소 지우기 | 사진에서 원하지 않는 물체 제거 | 명시적 브러시/다각형 마스크 | LaMa/ComfyUI | 일반 드래그와 마스크 모드를 분리, 마스크가 없으면 실행 불가를 명확히 |
| 여백/화각 넓히기 | 사진이 너무 타이트할 때 주변을 생성 | all/top/bottom/left/right, 5/10/15% | FLUX.1 Fill | 방향·비율을 사용자가 고르고 원본 내부가 유지된다는 기대를 표현 |
| 보는 위치 바꾸기 | 사진을 약하게 재해석 | left/right/up/down/dolly_out, subtle/standard | ViewCrafter | **현재 작동/선택 UX가 불명확함. 임의 변경이 아니라 방향·강도를 반드시 먼저 선택** |
| 빛 균형 맞추기 | 역광/조명 균형 개선 | front/left/right, strength | IC-Light | 단순 밝기 조절과 차이를 이해할 수 있는 의도 중심 카드 필요 |

### E-3. 성능·시연 주의

- LaMa, FLUX, IC-Light, ViewCrafter는 CAMP-2 GPU에서 실행한다.
- ViewCrafter와 FLUX는 수십 초~수 분이 걸릴 수 있다. 앱 이탈 후 재진입, 폴링 복원, 취소/실패 상태를 시연 품질 관점에서 점검한다.
- provider readiness가 참이어도 실기기에서 실제 후보 표시·저장 성공이 확인되지 않으면 기본 화면에 노출하지 않는다.
- 현재 실기기 보고상 AI 보정은 후보가 충분히 보이지 않고 흐름이 불편하다. 이는 기능 완료가 아니라 최우선 사용자 흐름 결함이다.

## 9. 시나리오 F — QR로 친구에게 ‘나 찍어줘’

```text
감도 사용자: 현재 자동 레이아웃 또는 수동 프레임 선택
→ QR 생성
→ 친구가 HTTPS 웹 링크를 열어 카메라 허용
→ 같은 고정 가이드 위에서 직접 최대 3장 촬영
→ 자동 업로드
→ 감도 앱 소유자가 도착 사진 확인
→ 수신·claim
→ 현재 감도 결과 화면으로 열기
```

| 기능 | 현재 상태 | 사용자 경험 | P1 점검/개선 요청 |
|---|---|---|---|
| 임시 세션 | 코어 구현 | 1시간, 최대 서버 업로드 5장 | QR 생성/만료 상태가 명확한지 |
| QR 정책 | 코어 구현 | 현재 고정 레이아웃의 슬롯·줌만 전달, 전체 프로필/사진은 전달하지 않음 | 공유 전 레이아웃 미리보기·12종 선택 UI |
| 웹 카메라 | 코어 구현/배포 확인 필요 | 풀스크린 카메라 + 같은 고정 브래킷 + 셔터 + 촬영 점 3개 | 처음 보는 촬영자도 설정·지시문 없이 찍을 수 있는지 |
| 웹 경량화 | 구현 | 웹에서 객체/포즈 AI 추론 없이 CSS/SVG 가이드만 그림 | 첫 프리뷰 3초, 셔터 반응 100ms 목표 |
| 웹 줌 | 제한 | 브라우저 capability가 있을 때만 정책 줌 적용 | 미지원 때 디지털 크롭·텍스트 지시 없음 |
| 웹 텍스트 | 계약 | 권한/오류/전송/완료 상태만 표시 | 정상 촬영 중 행동 지시 문구 없음 |
| 앱 수신·claim | 코어 구현 | 도착 사진 다운로드 후 세션 정리, 현재 감도로 결과 화면 열기 | P1 QR 화면, 2초 폴링, 사진 수, 받기/claim 연결 필요 |

QR은 정식 기본 흐름보다 데모 확장 기능이다. 하지만 시연한다면 **다른 기기에서 QR 열기 → 3장 촬영 → 앱 수신 → 내 감도 적용**까지 끊기지 않아야 한다.

## 12. P1 우선순위 제안 요청

P1은 아래 우선순위를 바탕으로 UI/UX 계획과 성능/시연 계획을 각각 제시해 달라.

### 최우선: 기본 데모가 끝나는 흐름

1. 온보딩 5장 선택 → 카메라 → 촬영 → 앨범 → 필터 적용 → 새 파일 저장
2. 카메라 필터 패널, `+ 내 필터 만들기`, 내 감도 적용 후 필터 목록 유지
3. AI로 보정에서 `내 감도로 정리하기`가 즉시 눈에 보이는 결과를 만들고 저장까지 이어지는 흐름
4. AI 생성 작업의 선택 → 파라미터 → 실행 → 진행 → 후보 비교 → 저장 흐름

### 다음: 카메라 가이드가 실제로 쓰이는 흐름

1. 풀블리드 프리뷰, HUD 기본 숨김, 작은 탐색 로딩
2. 자동 구도·탭 재탐색·고정 브래킷 표현
3. 프레임 버튼과 12종 수동 프레임 패널
4. 영역 선택 버튼·올가미 모드·완료·취소
5. 인물 브래킷/실루엣과 인물+소품 슬롯

### 확장 시연: 내 감도·QR·비교

1. 레퍼런스 사진 분석 → 범위 선택 → 내 감도 오버레이·색감 결과
2. QR 생성 → 다른 기기 웹 촬영 → 앱 수신/claim
3. 같은 장면, 다른 감도 비교와 데모 아카이브

## 13. P1 검토 후 반환 형식

P1은 각 시나리오에 대해 아래 형식으로 개선안을 작성해 달라.

```text
[시나리오/기능 이름]
현재 사용자 막힘:
UI/UX 개선안:
성능·시연 개선안:
필요한 P2 공개 상태/API:
화면 작업 범위:
완료 판정(실기기):
```

특히 다음 결함은 개선안에서 반드시 다뤄야 한다.

1. 올가미가 여러 물체를 감싸도 하나만 고정되는 현상(수정 반영 후 재검증).
2. `내 감도로 정리하기` 선택 후 눈에 보이는 결과가 없는 현상.
3. 내 감도 필터 선택 시 필터 목록/사진이 사라지는 현상.
4. 레퍼런스 색감이 참고 사진의 분위기보다 과포화·과대비로 보이는 현상.
5. AI 생성 후보가 도착했는지, 무엇을 선택해야 하는지, 저장됐는지 알기 어려운 흐름.
6. 수동 프레임·영역 선택·QR 수신처럼 P2 코어는 있으나 화면에서 진입할 수 없는 기능.

## 14. 최종 시연 체크리스트

### 기본 촬영

- [ ] 앱 데이터 삭제 후 온보딩 0개 시작, 카드 5장 선택, 카메라 진입
- [ ] 자동 구도 또는 수동 프레임으로 촬영
- [ ] 셔터 → 앨범 → 시스템 필터 → 새 파일 저장
- [ ] 내 감도 적용 뒤 필터 목록이 유지되고 색감 변화가 보임

### 레퍼런스 내 감도

- [ ] 사진 선택 → 동의 → 분석 → 구도/색감 범위 선택 → 적용
- [ ] 같은 사진 재선택은 캐시로 동작
- [ ] 카메라에서 레퍼런스 오버레이/투명도 조절
- [ ] 촬영 결과에서 내 감도 색감과 원본 비교

### 사진 살리기

- [ ] 앱 촬영 사진과 기기 사진 모두 AI로 보정 진입
- [ ] 내 감도로 정리하기가 즉시 결과를 표시
- [ ] 여백/시점/조명은 의도를 선택한 뒤에만 실행
- [ ] 후보 도착 → 비교 → 새 파일 저장
- [ ] 실패해도 원본·로컬 보정·저장 경로 유지

### 구도·QR 확장

- [ ] 영역 선택으로 감싼 객체 1~4개가 각각 고정 슬롯을 받음
- [ ] 영역 밖 바로 옆 객체가 포함되지 않음
- [ ] 수동 프레임 12종 선택 후 카메라 이탈 시 자동 탐색으로 초기화
- [ ] QR을 다른 기기에서 열어 3장 촬영 → 앱 수신 → 현재 감도 적용

## 15. 소유권 경계

- P1: 화면 구조, Compose UI, 버튼·패널·제스처, 로딩/실패/비교/저장 UX, 카메라 오버레이 렌더링, 최종 시연 화면 품질.
- P2: 온디바이스 객체·얼굴·레이아웃 로직, 레퍼런스 분석/로컬 상태, AI 3 controller·서버 계약, QR session/web 코어, 성능 계측.
- P1은 P2 공개 Controller/StateFlow를 사용하고, P2는 P1 소유 화면·디자인 파일을 임의로 수정하지 않는다.

이 문서는 기능을 모두 나열하기 위한 기준 문서다. 사용 가능 표기는 최종 품질 통과를 뜻하지 않으며, 위 체크리스트의 실기기 흐름이 끝까지 성공해야 시연 가능으로 판정한다.
