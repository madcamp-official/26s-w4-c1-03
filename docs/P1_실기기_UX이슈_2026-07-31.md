## 이슈 1. 내 감도 투명도 슬라이더가 필터 시트에 가려진다

### 현상

카메라에서 내 감도(레퍼런스)를 적용한 상태에서 투명도 슬라이더를 조작 중, 하단 필터 시트를 아래로 내리면 슬라이더가 시트 뒤로 가려져 조작할 수 없다.

### 원인

`ReferenceOverlayLayer`의 슬라이더는 프리뷰 Box 내부 `Alignment.BottomStart`에 `bottom = 12.dp`로 배치된다.

```
[ReferenceStrip.kt:234-254]
Row(
    modifier = Modifier
        .align(Alignment.BottomStart)
        .padding(start = 18.dp, bottom = 12.dp)  ← 프리뷰 하단에 고정
        ...
)
```

한편 `CameraPreviewPane`의 레이어 순서는:

```
camera preview → touch surface → referenceLayer() → guide overlay → aspect mask
```

`referenceLayer()`는 프리뷰 박스 안에 그려지지만, 필터/프레임 시트(`CameraSheetSlot`)는 프리뷰 박스 **바깥** 같은 Column의 **형제(sibling)**로 배치된다. 시트가 올라오면 `weight(1f)`인 프리뷰가 줄어들면서 슬라이더가 시트 영역과 겹치거나 숨겨진다.

### P1 수정 방향

- 슬라이더 위치를 프리뷰 내부 하단 고정이 아니라, **시트와 충돌하지 않는 영역**으로 이동하거나
- 시트가 열려 있을 때 슬라이더를 시트 상단으로 옮기거나
- 시트가 열려 있을 때 슬라이더를 일시 숨기고 시트가 닫히면 복원하거나

> ⚠️ `CameraScreen.kt:1983`의 레이어 순서 주석에 따르면 프리뷰 위에 별도 `pointerInput`을 추가하면 핀치줌·탭포커스가 죽는다. 슬라이더를 프리뷰 밖으로 빼는 경우 이 제약을 고려해야 한다.

## 이슈 2. 내 감도 만들기 앨범이 감도 폴더로 열린다

### 현상

카메라 또는 보정 화면의 필터 스트립에서 `+`(내 감도 만들기)를 탭하면 Android Photo Picker가 열리는데, 기본 위치가 `Pictures/감도` 폴더(앱 촬영본 저장 위치)로 열린다. 사용자는 레퍼런스로 쓸 **외부 사진**(인터넷 저장, 다른 앱 사진 등)을 고르려는 의도이므로 앱 촬영본 폴더가 먼저 보이는 것은 적절하지 않다.

### 원인

```kotlin
// [GamdoNavHost.kt:170-179]
val pickerLauncher = rememberLauncherForActivityResult(
    contract = ActivityResultContracts.PickVisualMedia(),
) { uri -> ... }

val onCreateReference: () -> Unit = {
    pickerLauncher.launch(PickVisualMediaRequest(ActivityResultContracts.PickVisualMedia.ImageOnly))
}
```

`PickVisualMedia`는 시스템 Photo Picker를 사용하며, **초기 폴더를 지정하는 API가 없다.** 시스템이 최근 저장 폴더를 기억하기 때문에, 앱이 `Pictures/감도`에 사진을 저장한 직후라면 Picker가 그 폴더를 먼저 보여준다.

### P1 수정 방향

- Android Photo Picker 자체에는 초기 디렉토리를 강제하는 파라미터가 없다 (시스템 동작)
- 가능한 우회:
  1. `ACTION_OPEN_DOCUMENT` + `INITIAL_URI`로 교체하면 초기 폴더를 지정할 수 있으나 Photo Picker의 UX(그리드 뷰)를 잃는다
  2. 사용자에게 "전체 사진에서 골라주세요" 같은 안내를 추가한다
  3. 현실적으로 **시스템 동작이므로 수용**하되, 시연 시 미리 다른 폴더의 사진을 한 번 열어 최근 위치를 바꿔놓는 것도 방법이다

> 이 이슈는 Android 시스템 Photo Picker의 제한이므로, 시연 전 워크어라운드를 정하는 것이 현실적이다.

## 이슈 3. 레이아웃 탭의 상황 칩(인물, 카페음식 등)이 무엇을 바꾸는지 모르겠다

### 현상

레이아웃 시트를 열면 상단에 **상황 칩** 행(자동 / 인물 / 배경 강조 인물 / 카페·음식 / 여행·풍경 / 정물 / 야간·거리)이 있고, 하단에 **수동 프레임** 행(자동 / 전신 중앙 / 전신 비대칭 / … / 12종)이 있다. 상황 칩을 바꿔도 화면에서 즉시 보이는 변화가 없어서 무엇이 달라지는지 알 수 없다. 오너 판단: **차라리 없는 게 나을 수도 있다.**

### 현재 동작

상황 칩은 `SceneModeChips`로 구현돼 있으며, 선택하면 `CaptureSceneMode`를 `SceneGuideSessionController`에 전달해 **자동 탐색 모드**의 후보 필터링을 바꾼다. 즉:

- 상황 칩 = 자동 탐색이 **어떤 종류의 장면을 우선 찾을지** 결정
- 수동 프레임 = 자동 탐색을 **무시하고** 고정 레이아웃을 즉시 적용

하지만 현재 상황 칩의 효과가 사용자에게 보이지 않는 이유:

1. **즉시 시각 변화가 없다** — 칩을 바꿔도 자동 탐색이 다시 돌 뿐, 즉각적 오버레이 변화가 없다
2. **분류기 모델이 아직 없다** — `AGENTS.md §9`에 따르면 MobileNetV3 장면 분류기와 YOLO11n-seg가 번들되기 전까지 보수적 휴리스틱으로 축소한다고 명시돼 있어, 칩을 바꿔도 실질적 분류 차이가 발생하지 않을 수 있다
3. **설명이 없다** — 칩이 무엇을 의미하는지 사용자에게 전달하는 텍스트·아이콘·애니메이션이 없다

### P1 수정 방향 (오너와 협의 필요)

| 방안 | 설명 |
|---|---|
| **A. 상황 칩 제거** | 오너 의견대로 현 시점에서 제거한다. 분류기 모델이 준비되고 효과가 체감될 때 다시 넣는다. 수동 프레임 행만 남긴다. |
| **B. 상황 칩 숨김** | 코드는 유지하되 UI에서 `visible = false`로 숨긴다. 시연 후 모델 준비 시 복원한다. |
| **C. 효과 시각화 추가** | 칩 선택 시 "인물 우선 탐색 중" 같은 피드백을 짧게 보여준다. 다만 D2(텍스트 지시 금지)에 걸릴 수 있다. |

> ⚠️ 상황 칩은 `SceneModeGuide.kt`(P2 소유, AGENTS.md §9 계약)의 `CaptureSceneMode`와 연결돼 있다. **UI 제거/숨김은 P1 소유**이고 P2 코드 수정은 불필요하다. `CameraFrameSheet`에서 `SceneModeChips` 호출을 제거하거나 조건부로 감추면 된다.
