# P1 디자인 통합 요청 — 장면 인식 고정 레이아웃

## 기준 브랜치

이 요청은 `main`의 **장면 단위 객체 인식·고정 레이아웃** 변경을 기준으로 한다.
P2는 탐지·장면 안정화·`SceneGuideSessionController` 계약을 제공했고, 카메라 화면의
시각 디자인과 상호작용은 P1이 최신 `main` 위에서 확정·푸시한다.

## 반드시 반영할 카메라 디자인

1. 자동 탐색 중에는 화면을 가리지 않는 작은 **비텍스트** 로딩만 보인다. 안내 문장,
   객체명, 신뢰도, 점수, HUD 디버그 정보는 데모 기본 화면에 노출하지 않는다.
2. 자동 장면이 고정되면 `GuideLayoutState.Fixed.template.slots`를 얇은 흰색 반투명
   구도 브래킷으로 렌더링한다. 슬롯은 피사체를 따라 이동하지 않고, 채움·비움·색상
   변화·일치도 상태를 표시하지 않는다.
3. 우측 상단 레이아웃 버튼은 `재탐색(AUTO)`과 제공된 9개 수동 레이아웃을 선택할 수
   있어야 한다. 수동 선택은 촬영 중 즉시 반영되며, 카메라 이탈 뒤에는 보존하지 않는다.
4. 셔터는 탐색·자동 고정·수동 고정 어떤 상태에서도 항상 활성화한다.
5. 카메라가 홈이라는 D11의 차콜·세이지 시각 체계를 유지한다. 사진·프리뷰가 주인공이
   되어야 하며, 오버레이·상단 컨트롤이 프리뷰보다 강하게 보이지 않게 한다.

## P2 연결 계약

- `CameraViewModel.layoutState: StateFlow<GuideLayoutState>`
- `CameraViewModel.availableManualLayouts`
- `CameraViewModel.selectManualLayout(templateId)`
- `CameraViewModel.rescanLayout()`

P2는 이번 통합에서 `CameraScreen`의 객체 탐지기 생성부만
`EfficientDetSceneDetector`로 교체했다. `CameraTopBar`, `CameraOverlay`, 수동 레이아웃
메뉴의 디자인·문구·애니메이션은 P1 소유이며, 이 요청 기준으로 개선 후 `main`에
푸시해야 한다.

## 완료 확인

- HUD 토글을 켜지 않은 상태의 기본 카메라 화면에서 디버그 문구가 보이지 않는다.
- 일반 물체 1~4개 또는 얼굴+물체 장면에서 고정 브래킷이 표시된다.
- 레이아웃 버튼으로 수동 선택·재탐색이 된다.
- 탐색 상태에서도 셔터와 앨범 진입이 막히지 않는다.

## P1 인수인계 메모

위 연결 계약과 화면 사용성을 기준으로 P1에서 최신 `main`에 통합해 주기 바람.
세부 시각 표현과 상호작용은 P1의 디자인 판단으로 완성하되, 계약에서 금지한 HUD·점수·상태색·행동 지시는 다시 노출하지 않도록 할 것.
요청 사항은 한쪽에 남겨두지 말고 실제 카메라·앨범·결과 흐름에 알아서 잘 반영해 주기 바람.
