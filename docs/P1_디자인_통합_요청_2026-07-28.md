# P1 디자인 통합 요청 — 장면 인식 고정 레이아웃·전체 UX 정리

## 기준 브랜치

이 요청은 `main`의 **장면 단위 객체 인식·고정 레이아웃** 변경을 기준으로 한다.
P2는 탐지·장면 안정화·`SceneGuideSessionController` 계약을 제공했고, 카메라 화면의
시각 디자인과 상호작용은 P1이 최신 `main` 위에서 확정·푸시한다.

## 반드시 반영할 카메라 디자인

1. 자동 탐색 중에는 화면을 가리지 않는 작은 **비텍스트** 로딩만 보인다. 안내 문장,
   객체명, 신뢰도, 점수, HUD 디버그 정보는 데모 기본 화면에 노출하지 않는다.
2. 자동 장면이 고정되면 `GuideLayoutState.Fixed.template.slots`를 얇은 흰색 반투명
   구도 브래킷으로 렌더링한다. 슬롯은 피사체를 따라 이동하지 않고, 채움·비움·색상
   변화·일치도 상태를 표시하지 않는다.
3. 우측 상단 레이아웃 버튼은 `재탐색(AUTO)`과 제공된 9개 수동 레이아웃을 선택할 수
   있어야 한다. 수동 선택은 촬영 중 즉시 반영되며, 카메라 이탈 뒤에는 보존하지 않는다.
4. 셔터는 탐색·자동 고정·수동 고정 어떤 상태에서도 항상 활성화한다.
5. 카메라가 홈이라는 D11의 차콜·세이지 시각 체계를 유지한다. 사진·프리뷰가 주인공이
   되어야 하며, 오버레이·상단 컨트롤이 프리뷰보다 강하게 보이지 않게 한다.

## P2 연결 계약

- `CameraViewModel.layoutState: StateFlow<GuideLayoutState>`
- `CameraViewModel.availableManualLayouts`
- `CameraViewModel.selectManualLayout(templateId)`
- `CameraViewModel.rescanLayout()`

P2는 이번 통합에서 `CameraScreen`의 객체 탐지기 생성부만
`EfficientDetSceneDetector`로 교체했다. `CameraTopBar`, `CameraOverlay`, 수동 레이아웃
메뉴의 디자인·문구·애니메이션은 P1 소유이며, 이 요청 기준으로 개선 후 `main`에
푸시해야 한다.

## 완료 확인

- HUD 토글을 켜지 않은 상태의 기본 카메라 화면에서 디버그 문구가 보이지 않는다.
- 일반 물체 1~4개 또는 얼굴+물체 장면에서 고정 브래킷이 표시된다.
- 레이아웃 버튼으로 수동 선택·재탐색이 된다.
- 탐색 상태에서도 셔터와 앨범 진입이 막히지 않는다.

## 2026-07-29 추가 요청 — 제품 의도를 가리는 화면 요소 정리

### 문제 정의

현재 구현은 기능 자체보다 화면이 먼저 혼란을 만든다. 사용자가 카메라를 열었을 때
`가이드 / HUD / 내 감도 적용 중 / 비율 / 구도`와 하단의 인물 썸네일 6개를 동시에
마주한다. 그러나 이 중 무엇이 촬영 구도를 바꾸고, 무엇이 촬영 뒤 색감을 바꾸며,
무엇이 개발용 정보인지 알 수 없다.

감도의 기본 흐름은 아래 세 문장으로 읽혀야 한다.

```text
1. 내가 좋아하는 감도를 고른다.
2. 감도가 제안한 구도에 맞춰 내가 직접 찍는다.
3. 찍은 사진에 같은 감도의 색감을 적용하거나 사진 살리기를 선택한다.
```

P1 화면은 이 흐름을 보조해야 하며, 일반 카메라 필터 앱·개발용 CV 데모처럼 읽혀서는
안 된다. P2는 이 문서에서 화면을 직접 수정하지 않고, 아래의 디자인·연결 요구를
전달한다.

### P0 — 카메라에서 바로 정리할 것

| 문제 | 현재 사용자 인상 | P1 변경 요청 | 완료 기준 |
|---|---|---|---|
| HUD가 Debug APK에서 기본 켜짐 | 객체 수·FPS·IoU·수평 수치가 제품 기능처럼 보이고 프리뷰를 가린다. | Debug 빌드여도 기본은 숨긴다. 개발 확인은 명시적 개발자 진입으로만 허용하고, 데모·일반 경로에서는 HUD와 원시 라벨을 절대 렌더링하지 않는다. | 앱을 처음 열어도 기술 수치·객체명·점수·원시 박스가 없다. |
| 상단 칩의 역할 중복 | `가이드`, `내 감도 적용 중`, `4:5/1:1`, `구도`가 모두 같은 중요도로 보인다. | 상단은 촬영 제어만 남긴다: 가이드 표시, 비율, 레이아웃 선택. `내 감도 적용 중` 상시 칩은 제거하고 선택된 감도는 스타일 선택 영역에서 한 번만 표현한다. 칩 수·강조색을 줄여 프리뷰가 주인공이 되게 한다. | 3초 안에 가이드 켜기·비율·구도 변경 위치를 구분할 수 있고, 상태 칩이 프리뷰보다 먼저 보이지 않는다. |
| `구도` 제어의 기능 불명확 또는 미연결 | 사용자는 자동 탐색·재탐색·수동 구도의 차이를 알 수 없고, 동작하지 않는 버튼이면 신뢰가 깨진다. | 우측 상단 `구도`는 실제 `availableManualLayouts`, `selectManualLayout`, `rescanLayout()`에 연결한다. 첫 항목은 `자동 탐색(재탐색)`, 나머지는 9개 수동 레이아웃이다. 아직 연결할 수 없으면 제품 화면에 버튼을 노출하지 않는다. | 자동·수동 선택이 즉시 브래킷을 바꾸며, 카메라 이탈 뒤 선택은 초기화된다. |
| 고정 레이아웃의 시각 무게 | 큰 반투명 사각형·강한 수평선은 사진 구도 제안보다 CV 디버그 그리드처럼 보인다. | `LayoutSlot`을 채워진 박스가 아니라 얇은 열린 브래킷으로 우선 표현한다. 인물은 실루엣, 사물은 작은 코너 브래킷의 차이를 사용한다. 수평선은 짧고 낮은 대비로 유지하며, 빨간 전체 폭 선이 화면을 지배하지 않게 한다. | 확정 뒤 슬롯은 고정되어 보이되, 사진 피사체와 셔터보다 강하게 보이지 않는다. |
| 탐색 상태의 노출 | 탐색 중 정보가 없거나 HUD를 켜야만 상태를 이해할 수 있다. | `GuideLayoutState.Searching` 동안 중앙 또는 프리뷰 가장자리에 작은 비텍스트 로딩만 표시한다. 안내 문장·점수·객체명은 넣지 않는다. | 물체가 없을 때도 오류처럼 보이지 않고, 셔터는 항상 사용할 수 있다. |

### P0 — 하단 스타일 행을 ‘필터 목록’이 아니라 ‘감도 선택’으로 바꿀 것

현재 `깔끔한 소셜`, `자연스러운 피드` 등의 6개 항목은 인물 사진 썸네일과 이름만
보여 준다. 사용자는 이를 실시간 필터인지, 인물 전용 프리셋인지, 구도 선택인지
판단할 수 없다. 이는 감도의 핵심인 **촬영 전 구도 + 촬영 후 색감**이라는 이중 역할을
가리는 가장 큰 요소다.

권장 표현은 다음과 같다.

1. 하단에는 현재 선택된 감도를 중심으로 보여 주고, 6종 전체 선택은 탭으로 여는
   `감도 선택` 시트 또는 접히는 패널로 제공한다. `+ 사진으로 만들기`와 `내 레퍼런스`
   역시 이 선택 구조 안에 넣어 별도 아이콘을 계속 늘어놓지 않는다. 셔터 위에 인물
   썸네일을 상시 나열해 일반 SNS 필터 앱처럼 보이게 하지 않는다.
2. 각 감도에는 이름 아래 한 줄의 일상어 결과를 붙인다. 예: `밝고 또렷하게`,
   `자연스럽고 편하게`, `부드럽고 따뜻하게`. 전문 구도 용어·수치·모델명은 금지한다.
3. 선택 상세에는 정적 예시로만 `찍을 때: 여백과 배치` / `찍은 뒤: 색감`의 두 결과를
   보여 준다. 이번 범위에서 라이브 카메라 컬러 셰이더를 약속하거나 흉내 내지 않는다.
4. 썸네일은 특정 인물 예시가 아니라 해당 감도의 색감·장면 인상을 보여 주는 이미지로
   교체한다. 동일한 인물 원형 6개는 ‘인물만 찍는 앱’으로 오해하게 한다.
5. 현재 선택 상태는 세이지 링만으로 끝내지 말고, 선택된 감도의 이름과 적용 범위를
   한 곳에서 읽을 수 있게 한다. 상단 상태 칩과 중복 표시는 하지 않는다.

완료 기준: 처음 쓰는 사람이 5초 안에 “이것은 사진을 찍기 전에 고르는 내 감도이며,
찍은 뒤 색감에도 이어진다”라고 설명할 수 있어야 한다.

### P1 — 나머지 화면의 일관성 정리

| 화면 | 제품 의도를 가리는 요소 | 개선 요청 |
|---|---|---|
| 온보딩 | `5장`을 골라야 하는 이유와 선택 결과가 약하다. | `0/5` 진행 상태와 함께 “좋아하는 사진으로 촬영 가이드와 색감을 정한다”는 결과를 명확히 보여 준다. 저장 완료 화면은 추천 감도·촬영·보정 반영을 하나의 짧은 흐름으로 보여 준다. |
| 앨범 | 빈 화면은 막다른 곳처럼 보이고, 실제 사진이 없을 때의 앨범 진입 목적이 약하다. | 빈 상태에는 카메라로 돌아가는 명확한 행동을 제공한다. 마지막 사진이 없을 때 카메라의 앨범 버튼에 그라데이션·가짜 썸네일을 쓰지 않고 중립적인 앨범 아이콘을 쓴다. 외부 사진 가져오기와 `사진 살리기` 진입은 AI 3 연결 시 같은 시각 체계로 추가한다. |
| 보정 결과 | `보정` 안에 원본·감도 색감·세부 조정·향후 사진 살리기가 한 층으로 섞일 위험이 크다. | 기본 경로를 `원본 → 내 감도 → 사진 살리기`로 읽히게 한다. 세부 조정은 기본 결과를 고른 뒤의 보조 패널로 내리고, AI 결과가 준비되지 않았을 때는 빈 후보 탭·가짜 결과를 보이지 않는다. `완료`와 `저장`은 역할을 분리한다: 완료는 편집 종료, 저장은 새 파일 생성. |
| 공통 컴포넌트 | 10~11sp 라벨, 비슷한 모양의 칩, 세이지의 과다 사용이 우선순위를 흐린다. | 보조 라벨은 읽을 수 있는 크기로 올리고, 세이지는 선택·주요 행동에만 사용한다. 상태·개발·보조 제어는 같은 강조색을 쓰지 않는다. |

### P2가 제공하는 연결 계약

P1은 화면을 새로 구성하더라도 아래 P2 계약을 그대로 사용하면 된다.

- 자동/수동 상태: `CameraViewModel.layoutState: StateFlow<GuideLayoutState>`
- 수동 레이아웃 목록: `CameraViewModel.availableManualLayouts`
- 수동 선택: `CameraViewModel.selectManualLayout(templateId)`
- 자동 재탐색: `CameraViewModel.rescanLayout()` 및 탭 재탐색 `rescanLayoutAt(x, y)`
- 고정 브래킷 입력: `SceneLayoutGuide.fixedLayout.template.slots`의 `role`, `visualKind`,
  정규화 `bounds`

P2는 레이아웃·탐색·스타일 데이터 계약을 유지한다. P1은 `CameraScreen`,
`CameraOverlay`, 온보딩·앨범·결과 화면의 시각 구조와 인터랙션을 담당한다. P1 화면
수정 뒤 P2는 실기기에서 자동 탐색·수동 레이아웃·스타일 선택·촬영·보정 저장의 연결만
재검증한다.

### 디자인 완료 판정

데모 경로에서 다음 질문에 UI만 보고 답할 수 있어야 한다.

1. 지금 카메라가 무엇을 찾고 있으며, 찾기 전에도 촬영할 수 있는가?
2. `내 감도`를 바꾸면 촬영 전과 촬영 후에 각각 무엇이 달라지는가?
3. 자동 구도와 수동 구도를 어디서 바꾸고, 재탐색은 무엇을 하는가?
4. 촬영 뒤에는 원본·내 감도·사진 살리기 중 어떤 흐름으로 이어지는가?

위 네 질문에 답할 수 없는 칩·문구·플레이스홀더·개발 수치는 제품 기본 화면에서
제거한다.
