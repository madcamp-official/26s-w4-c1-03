# P1 실기기 UX 수정 요청 — 온보딩부터 촬영·보정까지

작성일: 2026-07-29  
기준 기기: SM-S928N  
검증 범위: 앱 데이터 삭제 → 권한 → 온보딩 → 카메라 → 앨범 → 내 감도 → AI 보정 → 재실행 → 셔터  
담당: P1 화면·CameraX·Compose·내비게이션

## 1. 목적과 판정 기준

이 문서는 `docs/감도_전체기능_구현상태_2026-07-29.md`를 실사용자 흐름으로 다시 검증한 결과 중 P1이 수정하거나 연결해야 하는 항목만 정리한다. P2의 상태·탐지·서버 계약은 새로 재구현하지 않고 기존 공개 API를 화면에 정확히 연결한다.

완료는 화면이 존재하는지가 아니라 사용자가 다음 흐름을 설명 없이 끝까지 수행할 수 있는지를 기준으로 한다.

```text
처음 실행 → 취향 저장 → 촬영 → 앨범 → 내 감도 자동 보정 확인
→ 필요할 때만 AI 복구 → 결과 비교 → 새 파일 저장
```

## 2. 최우선 블로커

### P1-B1. 셔터 무한 로딩과 촬영 완료 콜백

실기기에서 셔터를 누르면 CameraX `takePictureInternal`까지 호출됐지만 성공·실패 콜백 없이 1분 이상 카메라 화면에 머물렀다. 중앙 로딩만 계속 표시되고 결과 화면으로 이동하지 않았다.

수정 요구:

- 셔터 요청을 중복 방지하는 단일 상태로 관리한다.
- 성공 시 저장 완료 후 최근 촬영 썸네일과 Room 기록을 갱신한다.
- 실패·타임아웃 시 촬영 상태를 반드시 해제해 다시 촬영할 수 있게 한다.
- 카메라 재바인딩과 촬영 callback lifecycle이 충돌하지 않는지 확인한다.
- 처리 중 사용자가 화면을 이탈하거나 앱이 background로 가는 경우 상태를 정리한다.
- 성공·실패·타임아웃을 Debug 로그로 구분하되 제품 화면에는 기술 오류를 노출하지 않는다.

완료 기준:

- 데이터 초기화 직후부터 촬영 5회가 모두 5초 이내 저장 또는 안전 복구된다.
- 한 번의 실패가 이후 촬영을 막지 않는다.

### P1-B2. 내 감도 적용 결과가 화면에서 사라짐

서버 분석과 P2 저장 로그는 성공했지만 완료 시트를 닫은 뒤 결과 화면에는 다시 `+ 내 감도`만 보였다. 생성한 `내 감도` 항목과 적용 결과는 보이지 않았다.

P1 연결 요구:

- 결과 화면은 일시적인 생성 시트 상태가 아니라 P2의 영속 `ResultFilterState`를 구독한다.
- `Applied → 시트 닫기`가 필터 목록을 초기화하지 않게 한다.
- 기본 6종은 항상 유지하고, 색감 capability가 있는 활성 레퍼런스를 일곱 번째 항목으로 표시한다.
- 필터 선택은 `selectedId`만 변경하고 목록 자체를 재생성·숨김 처리하지 않는다.
- 미리보기 렌더 실패 시 현재 사진의 원본을 표시하고 필터 목록은 유지한다.
- 앱 재구성·앨범 재진입·뒤로가기 후에도 활성 레퍼런스를 다시 표시한다.

P2가 활성 레퍼런스 상태를 정상적으로 내보내지 않는 경우에는 `docs/P2_실기기_기능수정기록_2026-07-29.md`의 P2-B2로 전달한다.

### P1-B3. 온보딩 약속과 결과 화면 기본값 불일치

온보딩은 “앞으로 촬영 가이드와 보정에 이 느낌을 자동으로 반영해요”라고 안내하지만, 사진을 열면 `원본`이 기본 선택된다.

수정 요구:

- 사진을 열었을 때 먼저 현재 감도의 로컬 보정 결과를 보여준다.
- 원본은 즉시 비교 가능한 항목으로 유지한다.
- `내 감도 만들기`와 `현재 내 감도 적용`을 동일한 `+ 내 감도` 문구로 표현하지 않는다.
- 활성 감도 이름 또는 대표 팔레트를 표시해 무엇이 적용됐는지 알 수 있게 한다.
- P2가 제공하는 자동 보정 결과가 없을 때만 원본을 안전 기본값으로 사용한다.

## 3. 온보딩과 권한

### P1-O1. 권한 요청 전 제품 가치 설명

- 현재 첫 화면은 큰 빈 공간과 권한 설명만 있어 사용자가 왜 권한을 주어야 하는지 알기 어렵다.
- “좋아하는 사진을 고르면 촬영 구도와 보정에 반영된다”는 핵심 흐름을 권한 요청 전에 짧게 보여준다.
- 전체 사진 접근 권한은 앱 실행 직후가 아니라 앨범 진입 시 요청하는 방식을 우선 검토한다.
- Photo Picker로 처리 가능한 레퍼런스 선택에는 전체 사진 권한을 요구하지 않는다.

### P1-O2. 취향 선택의 의미와 카드 접근성

- 카드 선택이 구도·색감·분위기 중 무엇을 결정하는지 한 문장으로 설명한다.
- 인물 사진에 편중되지 않도록 카드 배치는 P1 큐레이션 기준에서 균형을 맞춘다.
- 저장 전에 “이 선택으로 달라지는 것”을 구도·색감 미리보기로 연결한다.
- 모든 카드와 아이콘 버튼에 의미 있는 `contentDescription`을 제공한다.
- 선택 0개 시작과 최소 5장 조건은 유지한다.

## 4. 카메라 화면

### P1-C1. 제품용 화면과 Debug HUD 분리

- 앱 데이터 초기화 뒤에도 HUD가 기본 노출됐다. Debug 빌드라도 기본값은 숨김이어야 한다.
- HUD는 명시적인 개발자 동작으로만 켜고 제품 시연 경로에서는 유지되지 않게 한다.
- 원시 객체 수·FPS·IoU·match·fixed 같은 수치는 제품 화면에 표시하지 않는다.

### P1-C2. 풀블리드 촬영 화면과 접히는 패널

- 상단 `4:5/1:1` 칩을 제거하고 프리뷰를 안전 영역까지 풀블리드로 확장한다.
- 하단 6종 필터 스트립은 항상 보이지 않고 필터 버튼을 눌렀을 때만 패널로 연다.
- 필터 패널을 닫으면 셔터와 피사체가 중심이 되는 일반 카메라 화면으로 돌아간다.
- `내 감도 적용 중`은 어떤 감도와 어떤 범위가 적용되는지 최소 정보만 제공한다.
- `docs/P1_P2_카메라UX_AI개선_요구사항_2026-07-29.md`의 SNOW·갤럭시 카메라 참고 계약을 따른다.

### P1-C3. 탐색·고정 상태 렌더링

실측 상태가 `물체 0`, `fixed=none`인데 큰 사각 가이드가 표시됐다.

- P2 상태가 `Searching`이면 작은 비텍스트 로딩만 표시한다.
- `Fixed`일 때만 전달받은 고정 슬롯·포즈 가이드를 그린다.
- `fixed=none` 상태에서 임의 사각 프레임을 표시하지 않는다.
- 로딩은 화면 중앙을 가리지 않는 작은 위치에 둔다.
- 슬롯 채움 상태·색 전환·행동 지시 문구는 추가하지 않는다.

### P1-C4. P2 기능의 사용자 진입점 연결

다음 P2 코어가 구현돼 있으나 실제 화면에서 접근할 수 없었다.

- 영역 선택 버튼 → 드래그 경로 → `rescanInPolygon()`
- 프레임 버튼 → 12종 프레임 패널 → `selectManualLayout()`
- 자동으로 돌아가기/재탐색 → `rescan()`
- 인물 포즈 템플릿 → 고정 점·막대 렌더링
- 내 레퍼런스 원본 오버레이 → 투명도임을 알 수 있는 버튼과 0~60% 조절

## 5. 앨범과 결과 편집

### P1-R1. 앨범 정보 구조

- 앱 촬영 사진과 기기 사진을 구분하거나 필터링할 수 있게 한다.
- 최소한 날짜 그룹 또는 `감도로 찍은 사진` 진입점을 제공한다.
- 사진 셀에 접근성 설명을 제공한다.
- 사진 선택 즉시 결과 화면으로 이동하더라도 현재 선택 목적을 상단에서 알 수 있게 한다.

### P1-R2. 현재 사진 기반 필터 미리보기

- 결과 화면의 필터 썸네일은 고정 인물 사진이 아니라 현재 편집 중인 사진으로 렌더링한다.
- 미리보기 생성 중에는 원본 썸네일과 로딩을 사용하고 목록을 숨기지 않는다.
- 자주 쓰는 `원본 / 내 감도 / 다른 감도`를 우선 노출하고 세부 수동 조절은 접을 수 있게 한다.
- 밝기·온도·대비 등 다수의 조절값이 기본 화면을 압도하지 않게 고급 조절 패널로 정리한다.

## 6. AI 보정 화면

### P1-A1. 사용자의 감도 자동 보정을 첫 결과로 표시

현재 AI 보정은 “지울 수 있는 것들을 찾아볼게요”로 시작해 제품 의도와 다르다.

권장 흐름:

```text
AI로 보정
→ 내 감도 자동 보정 미리보기
→ 사진 상태가 나쁠 때만 화각·시점·조명 추천
→ 사용자가 실행
→ 원본/감도/AI 후보 비교
```

- 객체 삭제는 기본 진입 설명에서 제외하고 `직접 수정 → 지우기`로 둔다.
- 서버 진단 결과가 `local_style`뿐이면 별도 업로드 흐름을 반복하지 말고 로컬 결과를 바로 보여준다.
- 생성 작업이 추천되지 않아도 직접 수정에서 서버 capability가 준비된 작업을 선택할 수 있게 한다.
- 시점 변경은 방향·강도를 사용자가 확인할 수 있어야 한다.
- 추천이 없을 때 “이대로 두기”만 보여주지 말고 원본/감도 비교와 저장을 유지한다.

### P1-A2. 처리와 결과 피드백

- 분석·생성·다운로드 상태를 한 개의 비차단 진행 UI로 표현한다.
- 실행 전에는 서버 작업이 발생하지 않는다는 계약을 유지한다.
- 결과가 생기면 원본·내 감도·AI 후보를 같은 비교 화면에 유지한다.
- 생성 실패 시 기술 오류 대신 원본과 로컬 감도 결과를 유지한다.
