# 감도 추가 기능 제안서 — 취향을 촬영 정책으로 확장하기

문서 버전: 1.0  
작성일: 2026-07-29  
문서 성격: 현재 프로토타입 이후의 제품 확장 방향  
우선순위: 핵심 기반 → 촬영 후 확장 → 공유 촬영 → 웹 아카이브

## 1. 제안 요약

감도를 단순한 필터 추천 앱이나 정답 구도를 알려주는 카메라로 확장하지 않는다. 사용자가 좋아하는 사진을 분석해 **상황별 촬영 정책**을 만들고, 본인이 촬영할 때와 다른 사람에게 촬영을 부탁할 때, 과거 사진을 다시 해석할 때까지 같은 취향을 일관되게 사용하는 제품으로 확장한다.

제품 정의:

> 감도는 내가 좋아하는 사진을 상황별 촬영 규칙으로 학습하고, 내가 찍거나 다른 사람이 찍을 때도 그 취향을 재현해 주는 카메라다.

기능 위계는 다음으로 고정한다.

```text
핵심 기반    상황별 감도 프로필
대표 확장    나 찍어줘
촬영 후 확장 지금의 감도로 다시
검증·시연    같은 장면, 다른 감도
후순위 웹    감도 아카이브
제외         우리 감도
```

## 2. 해결하려는 사용자 문제

사용자는 사진을 부탁할 때 자신의 취향을 구체적으로 설명하기 어렵다.

- 친구는 광각으로 찍지만 사용자는 2배 망원을 선호한다.
- 전신사진을 원했는데 얼굴 중심으로 촬영된다.
- 야간 플래시, 카메라 높이, 인물 위치를 매번 설명하기 민망하다.
- 사용자가 다른 사람을 찍은 사진과 다른 사람이 사용자를 찍은 사진의 품질 차이가 크다.
- 과거 사진의 장소와 표정은 좋지만 현재 취향과 구도·색감이 다르다.
- 기존 AI 편집은 사용자의 취향보다 일반적인 미화나 객체 삭제를 우선한다.

감도는 하나의 보편적인 좋은 구도를 제시하지 않는다. 상황과 사람에 따라 다른 사용자의 정답을 촬영 가능한 규칙으로 변환한다.

## 3. 핵심 기반 — 상황별 감도 프로필

### 3.1 개념

기존의 단일 추천 프리셋을 상황별 촬영 정책으로 확장한다.

```text
좋아하는 사진 + 직접 촬영한 사진 + 사용 행동
→ 사진별 특징과 촬영 정보 분석
→ 상황별 선호 규칙 생성
→ 촬영 가이드·자동 보정·생성 복구에서 공통 사용
```

프로필은 `빈티지 72%`처럼 설명에만 쓰이는 진단이 아니라 실제 촬영과 보정에 사용할 수 있어야 한다.

예시:

> 종화의 감도  
> 야간에는 플래시를 사용하고 인물을 화면 중앙보다 약간 아래에 배치합니다.  
> 야외 전신사진에서는 2배 줌과 낮은 카메라 높이를 선호합니다.  
> 완벽히 정돈된 사진보다 약간 즉흥적인 구도를 좋아합니다.

### 3.2 분석 영역

| 영역 | 분석 결과 예시 | 사용 위치 |
|---|---|---|
| 렌즈·화각 | 광각, 1배, 2배 선호 | 촬영 정책 |
| 거리·인물 비중 | 얼굴 중심, 전신, 배경 포함 | 레이아웃 |
| 앵글 | 눈높이, 로우 앵글, 기울어진 구도 | 촬영 가이드 |
| 플래시·조명 | 야간 플래시, 자연광, 역광 선호 | 촬영·재조명 |
| 배치·여백 | 중앙, 비대칭, 배경 여백 | 고정 프레임 |
| 인물 표현 | 정면, 자연스러운 순간, 움직임 | 포즈 템플릿 |
| 색감 | 채도, 대비, 색온도, 노출 | 로컬 보정 |
| 질감 | 선명도, 그레인, 약한 흔들림 | 결과 렌더링 |

### 3.3 상황별 정책 예시

```text
야간 + 인물
→ 플래시 선호, 1배, 인물 중앙, 강한 대비

카페 + 음식
→ 2배 또는 근접, 따뜻한 색감, 대각 배치

야외 + 전신
→ 낮은 카메라 위치, 2배, 머리 위 여백 최소화

단체 사진
→ 광각, 비대칭 배치, 자연스러운 포즈
```

### 3.4 근거와 신뢰도

사진만 보고 모든 촬영 정보를 확정하지 않는다. 각 정책은 근거와 신뢰도를 가진다.

- EXIF가 있으면 초점거리·기기·플래시 여부를 직접 사용한다.
- 구도·인물 비중·여백·색감은 이미지에서 분석한다.
- EXIF가 없는 캡처·Pinterest 이미지는 카메라 높이·거리·렌즈를 추정값으로만 사용한다.
- 좋아하는 사진과 직접 찍은 사진을 구분한다.
- 저장·삭제·필터 선택 같은 실제 행동을 후속 보정 신호로 사용한다.

예시 데이터:

```json
{
  "context": "outdoor_full_body",
  "rule": "prefer_2x_low_angle",
  "evidence": "exif_and_composition",
  "confidence": 0.82,
  "sampleCount": 12
}
```

### 3.5 사용자 입력량

- 첫 온보딩은 현재처럼 5장으로 빠르게 시작한다.
- 10~20장 분석은 선택형 `내 감도 더 정확하게 만들기`로 제공한다.
- 앱 사용 중 저장·삭제·다시 보정한 행동으로 프로필을 점진적으로 갱신한다.
- 신뢰도가 낮은 규칙은 강제하지 않고 일반 감도 프리셋을 사용한다.

## 4. 대표 확장 — 나 찍어줘

### 4.1 사용자 가치

사용자가 사진을 부탁할 때 취향을 직접 설명하지 않아도 상대방 카메라에 전달한다.

```text
사용자: 나 찍어줘 생성
→ 상황별 감도 정책 선택 또는 자동 추정
→ QR 코드·링크 공유

촬영자: 링크 열기
→ 카메라 권한 허용
→ 고정 레이아웃에 사용자를 맞춤
→ 수동으로 3장 촬영
→ 소유자의 감도로 보정
→ 결과 전달
```

### 4.2 웹 카메라 MVP

촬영자는 감도 앱을 설치하지 않아도 모바일 웹으로 접속할 수 있다.

1차 범위:

- HTTPS 모바일 웹 카메라
- QR·공유 링크로 읽기 전용 감도 정책 전달
- 전신·상반신·배경 비중에 맞는 고정 레이아웃
- 세로·가로, 인물 위치, 카메라 높이의 간단한 시각 표현
- 지원 기기에서만 렌즈·줌 capability 적용
- 수동 촬영 3장
- 촬영 후 감도 색감 자동 적용
- 원 사용자에게 결과 전달 또는 일회성 다운로드

브라우저·기기에 따라 줌·플래시를 제어할 수 없을 수 있으므로 capability를 먼저 확인한다. 지원되지 않는 기능은 강제하지 않고 시각 안내 또는 일반 촬영으로 축소한다.

### 4.3 제품 원칙

- 촬영자를 교육하는 복잡한 분석 화면을 만들지 않는다.
- 원 사용자의 감도 규칙 중 현재 기기에서 실행 가능한 것만 사용한다.
- 자동 촬영은 초기 범위에서 제외하고 사용자가 직접 셔터를 누른다.
- 촬영 링크는 편집 가능한 프로필이 아니라 해당 세션용 읽기 전용 스냅샷이다.
- 링크가 없어져도 원 사용자의 전체 감도 프로필이 노출되지 않는다.

## 5. 촬영 후 확장 — 지금의 감도로 다시

### 5.1 재정의

기존 사진 살리기를 일반적인 AI 삭제·확장 도구가 아니라 다음 질문에 답하는 기능으로 바꾼다.

> 지금의 내가 그때 그 장면을 찍었다면 어떻게 달라졌을까?

```text
과거 사진 선택
→ 현재 감도와 차이 분석
→ 현재 감도 자동 보정 결과 우선 제시
→ 재해석 강도 선택
→ 필요한 생성 작업 실행
→ 원본과 비교·저장
```

### 5.2 재해석 수준

| 단계 | 사용자 의미 | 내부 처리 |
|---|---|---|
| 기억 보존 | 장면은 그대로 두고 보기 좋게 | 밝기·색감·수평·가벼운 크롭 |
| 감도 적용 | 현재 취향에 맞게 정리 | 여백 확장·배경 정리·조명 재구성 |
| 다시 찍었다면 | 현재 취향으로 적극 재해석 | 화각·시점·구도 생성 복구 |

### 5.3 기술 매핑

| 목적 | 내부 기술 |
|---|---|
| 현재 감도 색감 | LocalEditor·Reference ColorTarget |
| 배경 방해 요소 정리 | LaMa |
| 좁거나 잘린 화각 복구 | FLUX Outpaint |
| 역광·조명 균형 | IC-Light |
| 촬영 위치·시점 재해석 | ViewCrafter |
| 인물·피사체 보존 검증 | InsightFace·객체 검증 |

사용자 화면에는 모델명이나 작업명을 우선 노출하지 않는다. `지우기`, `여백 늘리기`, `보는 위치 바꾸기`는 고급 직접 수정으로 내리고 기본 경로에서는 감도 기준 자동 결과를 먼저 보여준다.

## 6. 검증·시연 — 같은 장면, 다른 감도

이 기능은 독립적인 메인 기능보다 감도 프로필의 차이를 검증하고 보여주는 비교 모드로 사용한다.

```text
같은 장소·인물·기기
→ A 감도 적용 촬영
→ B 감도 적용 촬영
→ 구도·줌·색감 결과 나란히 비교
```

예시:

| A의 감도 | B의 감도 |
|---|---|
| 플래시 | 자연광 |
| 1배 | 2배 |
| 인물 중앙 | 여백 많은 비대칭 |
| 강한 대비 | 낮은 채도 |
| 즉흥적인 기울기 | 안정적인 수평 |

이 비교는 다음 메시지를 설명 없이 전달해야 한다.

> 사진을 잘 찍는 방법은 하나가 아닙니다. 감도는 정답을 알려주는 대신 각자가 좋아하는 방식으로 찍도록 돕습니다.

구현 형태는 개발용 비교 화면 또는 결과 화면의 프로필 전환으로 제한한다. 별도 메인 탭은 만들지 않는다.

## 7. 후순위 웹 — 감도 아카이브

### 7.1 역할

웹을 제작 관리 도구나 일반 갤러리로 만들지 않는다. 사용자의 시각적 취향이 어떻게 변했는지 관찰하는 공간으로 정의한다.

웹 콘텐츠 후보:

- 현재 감도 프로필
- 상황별 촬영 습관
- 내가 찍은 사진과 남이 찍어준 사진의 차이
- 저장·삭제한 결과의 특성
- 학기별·연도별 취향 변화
- 과거 사진 원본과 현재 감도 재해석 비교
- 공유 가능한 읽기 전용 감도 카드

예시 문구:

> 2025년에는 따뜻하고 정돈된 사진을 선호했습니다.  
> 2026년에는 플래시와 강한 대비를 더 자주 선택합니다.  
> 얼굴만 크게 담기보다 장소와 순간을 함께 남기는 경향이 강해졌습니다.

### 7.2 데모 데이터 운영

웹 아카이브는 후순위이며, 초기 데모에서는 실제 장기 사용 데이터 대신 명시적으로 준비한 샘플 프로필·기간별 통계·비교 사진 메타데이터를 사용할 수 있다.

허용:

- `demo_profile_2025`, `demo_profile_2026` 같은 고정 샘플 프로필
- 샘플 촬영 습관·취향 변화 그래프
- 데모용으로 사전에 준비한 원본·재해석 비교 결과
- 데모 계정 없이 하나의 읽기 전용 아카이브 화면

금지:

- 실제 분석·생성에 성공한 것처럼 가짜 API 응답을 사용자 기능에 연결
- 고정 결과 이미지를 실시간 생성 결과로 위장
- 더미 통계를 실제 사용자 측정치로 표현

데모 데이터에는 코드와 화면에서 `demo` 출처를 남긴다. 발표 화면에서는 서비스 방향을 보여주는 예시 데이터임을 명확히 설명한다.

### 7.3 정식 구현 전제

정식 아카이브는 충분한 행동 데이터와 계정·동기화 정책이 필요하다. 현재의 로그인 없음·로컬 저장 계약을 유지하는 동안에는 앱 내부 아카이브 또는 명시적 내보내기 파일로 시작한다.

## 8. 제외 — 우리 감도

여러 사람의 감도를 합치는 `우리 감도`는 현재 구현 범위에서 제외한다.

제외 이유:

- 계정·초대·그룹 관리가 필요하다.
- 취향 충돌과 합의 규칙이 복잡하다.
- 단체사진의 중심 인물·결과 공유 문제가 추가된다.
- 감도 프로필·나 찍어줘·현재 감도 재해석보다 핵심 사용자 문제와 거리가 있다.

아이디어는 후보군으로만 보존하고 실제 사용자 요구가 확인될 때 다시 검토한다.

## 9. 데이터·기술 구조 제안

### 9.1 공통 정책 모델

```text
GamdoProfile
├─ globalPreference
├─ contextPolicies[]
│  ├─ context: night_person | cafe_food | outdoor_full_body ...
│  ├─ capture: lens, distance, angle, flash, framing, pose
│  ├─ color: temperature, exposure, contrast, saturation, grain
│  ├─ evidence
│  └─ confidence
└─ updatedAt
```

모든 기능은 별도 취향 모델을 만들지 않고 같은 정책을 사용한다.

```text
카메라 가이드       → capture 정책
촬영 후 자동 보정   → color 정책
나 찍어줘           → 세션용 정책 스냅샷
지금의 감도로 다시  → capture + color 정책과 원본 차이
감도 아카이브       → 정책 변화 이력
```

### 9.2 상황 선택

상황은 자동 분석을 기본으로 하되 사용자가 바꿀 수 있어야 한다.

- 인물·전신·상반신
- 카페·음식
- 야간
- 풍경·장소
- 단체
- 일반 장면

자동 분석의 확신이 낮으면 전역 감도 규칙을 사용한다. 잘못된 상황을 강제하는 것보다 일반 감도로 안전하게 축소한다.

## 10. 구현 우선순위

### Phase 1 — 프로필 계약

1. 현재 5장 온보딩 결과를 `GamdoProfile` 초기값으로 변환한다.
2. 사진 특징·EXIF·사용 행동의 근거와 신뢰도 구조를 정의한다.
3. 촬영 가이드와 LocalEditor가 같은 상황별 정책을 사용한다.
4. 현재 적용된 정책을 Debug 상태에서 검증한다.

### Phase 2 — 지금의 감도로 다시

1. 사진과 현재 프로필의 차이를 진단한다.
2. 내 감도 로컬 보정 결과를 첫 결과로 제공한다.
3. 기억 보존·감도 적용·다시 찍었다면 단계를 연결한다.
4. LaMa·FLUX·IC-Light·ViewCrafter를 목적별 내부 도구로 사용한다.

### Phase 3 — 같은 장면, 다른 감도

1. 프로필 A/B 전환 비교 화면을 만든다.
2. 같은 장면에서 구도·줌·색감 차이를 검증한다.
3. 프로필 규칙이 실제로 다른 결과를 만드는지 품질 평가에 사용한다.

### Phase 4 — 나 찍어줘

1. 읽기 전용 세션 정책과 QR 링크를 만든다.
2. 모바일 웹 카메라와 고정 레이아웃을 구현한다.
3. 브라우저 capability별 줌·플래시 축소 경로를 둔다.
4. 수동 촬영 3장과 감도 보정·결과 전달을 연결한다.

### Phase 5 — 감도 아카이브 데모

1. 명시적인 샘플 프로필과 변화 데이터를 만든다.
2. 읽기 전용 단일 웹 아카이브를 구현한다.
3. 앱의 실제 누적 데이터가 생기면 더미 데이터를 교체한다.

## 11. 성공 기준

### 감도 프로필

- 사용자가 자신의 프로필 설명을 읽고 실제 취향과 비슷하다고 판단한다.
- 같은 상황에서 다른 프로필이 서로 다른 촬영·보정 결과를 만든다.
- 프로필 규칙의 근거와 신뢰도를 추적할 수 있다.

### 나 찍어줘

- QR 진입부터 첫 촬영까지 앱 설치 없이 1분 이내다.
- 촬영자는 별도 설명 없이 고정 레이아웃을 사용할 수 있다.
- 미지원 카메라 capability에서도 촬영 자체는 중단되지 않는다.

### 지금의 감도로 다시

- AI 도구를 고르지 않아도 현재 감도의 첫 결과를 확인할 수 있다.
- 세 단계의 차이가 사용자에게 명확하다.
- 생성 실패 시 원본과 로컬 감도 결과는 항상 유지된다.

### 감도 아카이브

- 데모 데이터와 실제 데이터를 명확히 구분한다.
- 일반 사진 갤러리가 아니라 취향 변화 기록으로 이해된다.

## 12. 최종 제안

당장 웹부터 만들지 않는다. 먼저 감도 프로필을 상황별 촬영 정책으로 정의하고 현재 카메라·보정·AI 3가 같은 정책을 사용하게 한다. 이후 `지금의 감도로 다시`로 생성 AI의 목적을 정리하고, `같은 장면, 다른 감도`로 차이를 검증한다.

`나 찍어줘`는 감도의 대표 확장이지만 모바일 웹 capability 차이를 감안해 고정 레이아웃·수동 촬영 중심 MVP로 시작한다. 감도 아카이브는 후순위로 구현하며 데모 시연에는 출처가 명확한 샘플 데이터를 사용할 수 있다. `우리 감도`는 현재 범위에서 제외한다.
