# P2 → P1 필수 기능 연결 요구사항

작성일: 2026-07-30

감사 기준: `main` `ec3860e`

상태: **기능 연결 계약 — 시각 디자인은 P1 재량**

## 1. 이 문서가 요구하는 것과 요구하지 않는 것

P2는 기능을 사용할 수 있게 만드는 상태·이벤트·좌표·서버 계약을 제공한다. P1은 이를
사용자 화면에 연결한다. 버튼의 모양, 위치, 색, 문구, 패널 높이, 애니메이션, 화면 밀도와
같은 순수 디자인 판단은 P1에게 온전히 위임한다.

이 문서가 강제하는 것은 다음 세 가지뿐이다.

1. 사용자가 구현된 기능에 실제로 진입할 수 있어야 한다.
2. 화면 조작이 P2의 공개 API와 정확히 연결되어야 한다.
3. 기능의 성공·취소·재진입 상태가 끊기지 않아야 한다.

따라서 기존 문서에 있는 `SNOW처럼`, 특정 아이콘, 세이지 테두리, 하단 팝업, 버튼 위치,
슬라이더 형태 등의 문장은 참고사항이지 완료 조건이 아니다. 이 문서와 기존 P1 요청 문서의
시각 표현이 충돌하면 P1 판단을 따른다. 반대로 아래 진입점과 상태 연결은 디자인 선택으로
생략할 수 없다.

## 3. P0 — 카메라에서 반드시 연결할 기능

### 3.1 수동 프레임 선택

P1은 어떤 형태로든 다음 동작에 도달 가능한 조작을 제공한다.

```text
사용자 진입
→ CameraViewModel.availableManualLayouts 표시
→ 항목 선택
→ CameraViewModel.selectManualLayout(templateId)
→ GuideLayoutState.Fixed(source=MANUAL) 렌더
→ 자동으로 돌아가기/재탐색
→ CameraViewModel.rescanLayout()
```

필수 조건:

- 프레임 목록을 하드코딩하지 않고 `availableManualLayouts`에서 읽는다.
- 선택 실패(`false`)를 고정 성공으로 표시하지 않는다.
- 수동 선택 후에도 셔터를 사용할 수 있다.
- 카메라 세션을 나갔다 돌아오면 기본 자동 탐색으로 복귀한다.
- P1은 목록·선택 화면의 시각 형식을 자유롭게 결정한다.

### 3.2 드래그 영역 선택 — 코드 연결 완료, 실기기 판정 대기

P1 최신 병합본에서 명시적 영역 선택 모드와 다각형 제출·취소 연결은 완료됐다. 이 항목은
추가 디자인 요구가 아니라 다음 기능 검증만 남긴다.

```text
영역 선택 모드 진입
→ 프리뷰 위 경로 수집
→ 손을 떼면 points + PreviewGeometry 전달
→ CameraViewModel.rescanLayoutInPolygon(points, geometry)
→ true: 탐색 상태 렌더
→ false: 기존 자동/고정 상태 유지
→ 취소 시 CameraViewModel.cancelPolygonLayoutSearch()
```

필수 조건:

- 영역 선택 모드가 아닐 때 드래그를 다각형 입력으로 보내지 않는다.
- 화면 픽셀을 임의 정규화하지 않고 현재 `PreviewGeometry`를 함께 전달한다.
- `false` 결과를 성공처럼 표시하거나 기존 고정을 지우지 않는다.
- 수동 프레임·레퍼런스 적용으로 전환하면 영역 선택 입력을 종료한다.
- 선택선, 아이콘, 취소 방식과 애니메이션은 P1이 결정한다.

최신 코드에는 위 조건을 위한 호출 경로가 존재한다. 실제 물체가 선택 영역 안팎으로 나뉘는
장면에서 후보 제한, 잘못된 작은 경로 거부, 취소 후 기본 자동 탐색 복귀를 실기기로 판정한다.

### 3.3 인물 슬롯 표현

P2가 전달한 `LayoutSlot.visualKind`를 렌더링 계층에서 소비한다.

- `PERSON_BRACKET` 또는 `PERSON_SILHOUETTE`: 인물 목표임을 사용자가 구분할 수 있어야 한다.
- `GENERIC_OBJECT`, `CUP`, `PLATE`: 일반 객체 목표로 처리한다.
- 인물 1명과 물체가 함께 선택되면 전달된 모든 슬롯을 렌더한다.
- 점·막대 포즈, 정렬 점수, 자동 촬영은 다시 추가하지 않는다.

인물 실루엣의 스타일과 브래킷 형태는 P1의 디자인 영역이다. 필수 조건은 P2의 슬롯 역할을
버리지 않는 것이다.

### 3.4 촬영 비율 계약 — 화면 연결 완료, 종단 검증 대기

오너 결정으로 `4:5 / 1:1 / 16:9`를 제공한다면 아래 네 위치가 같은 선택값을 사용해야 한다.

1. 카메라 선택 상태 `CaptureAspect`
2. 프리뷰 마스크와 `PreviewGeometry`
3. `ImageCapture` crop 및 저장 결과
4. 결과 편집기의 `EditAspect.nearest()`

최신 P1 병합본은 `CaptureAspect.RATIO_16_9`, 프리뷰 마스크와 촬영 crop 전달을 추가했다.
따라서 P1에게 새로운 디자인을 요구하지 않는다. 다만 16:9 촬영 파일을 결과 화면에서 다시
열었을 때 동일 비율이 유지되는지, 가이드 좌표가 프리뷰와 저장 결과에서 어긋나지 않는지는
실기기에서 종단 검증해야 한다. 현재 가이드 스타일 입력이 16:9를 `FOUR_TO_FIVE`로 축약하는
부분은 P2 기능 검증 대상으로 둔다.

## 4. P0 — AI 보정의 필수 기능 연결

현재 추천 카드 선택→명시적 실행→submit 연결은 존재한다. 추가로 `직접 수정` 경로에서는
서버가 준비됐다고 응답한 작업을 추천 여부와 무관하게 선택할 수 있어야 한다.

| capability | 필수 사용자 입력 | operation |
|---|---|---|
| `removeObjects` | 유효한 마스크 | `remove_objects` |
| `outpaint` | 방향, 5·10·15% | `outpaint` |
| `viewpoint` | 방향, 강도 | `viewpoint` |
| `relight` | 조명 방향 또는 의도, 강도 | `relight` |

필수 조건:

- capability가 `false`인 작업은 실행할 수 없게 한다.
- 사용자가 작업과 파라미터를 확정하기 전 `edit-job`을 생성하지 않는다.
- 한 번의 실행 동작에서 job을 정확히 한 번 생성한다.
- 화면 이탈·재진입 뒤 진행 중 job의 폴링 상태를 복원한다.
- 후보가 없거나 실패하면 원본과 로컬 감도 결과를 유지한다.
- 추천 카드, 직접 수정 화면, 비교 화면의 형태는 P1이 결정한다.

## 5. P1 — QR `나 찍어줘` 필수 연결

QR 기능을 제품 기능으로 표시하려면 다음 흐름 전체가 연결돼야 한다.

```text
현재 고정 레이아웃 또는 사용자가 고른 수동 레이아웃
→ ShootPolicyV2.fromTemplate(...)
→ ShootSessionRepository.create(policy)
→ ShootQrCode.encode(session.shareUrl)
→ snapshot을 2초 간격으로 refresh
→ 도착 사진 수 확인
→ receiveAndClaim(session)
→ 받은 사진을 기존 결과 화면으로 열기
```

필수 조건:

- 레이아웃이 없을 때 임의의 잘못된 정책을 조용히 전송하지 않는다. P1이 사용자에게 기본
  프레임 선택 또는 취소 중 하나를 제공한다.
- QR에는 서버가 발급한 절대 `shareUrl`만 넣는다.
- 만료·오류·도착 사진 없음·수신 가능 상태를 구분한다.
- 수신 성공 후 기존 앨범 사진과 같은 결과·저장 흐름으로 연다.
- `receiveAndClaim()` 성공 후 세션이 정리돼야 한다.
- QR 화면의 배치·문구·미리보기 방식은 P1이 결정한다.

QR 기능을 아직 연결하지 않는다면 제품 화면에 진입점을 노출하지 않고 **미구현**으로 표시한다.
P2 코어가 존재한다는 이유만으로 사용자 기능 완료로 계산하지 않는다.

## 6. 후순위 기능의 연결 경계

다음 기능은 핵심 촬영 흐름의 P0는 아니지만, 시연하거나 구현 완료로 보고하려면 진입점이
필요하다.

### 프로필 정교화

- `ProfileRefinementRepository`를 호출하는 사진 선택 경로
- 처리 중·성공·재시도 상태
- 완료된 프로필을 현재 감도에 반영

### 같은 장면·다른 감도

- `GamdoComparisonEngine.compare(...)` 호출
- 현재 감도와 데모 감도를 같은 입력으로 비교
- 데모 결과임을 기능적으로 구분하는 표시

화면 구성은 P1이 결정하며, 이번 P0 연결 완료를 막지는 않는다.

## 7. P2 자체 잔여 작업과 검증

아래는 P1 디자인 책임으로 넘길 수 없는 P2 영역이다.

- 수동·다각형·인물+객체 슬롯의 실기기 반복 검증
- QR V2 정책 생성→웹 config→3장 업로드→앱 수신→claim 종단 검증
- LaMa·FLUX·IC-Light·ViewCrafter 작업별 실제 후보와 실패 폴백 검증
- 실행은 비활성화됐지만 남아 있는 legacy pose 타입·설정·주석의 후속 정리
- 최신 P1 통합본에서 객체 분석 FPS·드롭·첫 고정 시간 재측정

이 항목은 P1이 버튼을 연결했다고 자동 완료되지 않는다.

## 8. 기능 연결 완료 체크리스트

- [ ] 수동 프레임 목록이 P2 카탈로그에서 열리고 선택·자동 복귀가 동작한다.
- [x] 영역 선택 모드의 경로 수집·제출·취소 코드가 P2 API에 연결됐다.
- [ ] 영역 안팎 객체 제한과 취소 복귀를 실기기에서 확인한다.
- [ ] 인물 슬롯의 `visualKind`가 일반 객체 슬롯과 구분되어 렌더링된다.
- [x] 16:9 선택과 프리뷰 마스크·촬영 crop 코드가 연결됐다.
- [ ] 16:9 프리뷰·촬영·저장·편집·가이드 좌표가 실기기에서 동일하다.
- [x] 결과 화면이 `ResultFilterStateHolder`를 단일 목록 상태로 사용한다.
- [ ] capability가 준비된 AI 작업을 추천 여부와 무관하게 직접 실행할 수 있다.
- [ ] AI 실행 전 job 0회, 실행 후 job 1회, 재진입 폴링 복원이 확인된다.
- [ ] QR 생성→웹 촬영→앱 수신→claim 흐름이 연결된다.
- [ ] 위 흐름을 최신 APK와 실제 기기에서 검증한다.

## 9. P1에 전달할 최종 요약

P1은 P2가 제안했던 특정 화면 모양을 따를 의무가 없다. 필요한 것은 다음 기능이 사용자에게
실제로 열려 있고 P2 공개 API와 연결되는 것이다.

```text
수동 프레임 선택
인물 슬롯 역할 렌더링
준비된 AI 작업의 명시적 실행
QR 생성·수신
```

영역 선택과 16:9는 최신 P1 코드에 연결됐으므로 새 디자인 요청에서 제외한다. 다만 두 기능의
