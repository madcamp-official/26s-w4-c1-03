# AI 3 사진 살리기 통합 계약

문서 기준일: 2026-07-28

## 현재 구현 상태

AI 3은 앨범에서 사용자가 선택한 사진을 기준으로 동작한다. 라이브 카메라 프레임은 업로드하지 않는다.

```text
앨범 사진 선택
→ POST /api/v1/rescue/analyze
→ 추천 확인
→ 사용자가 작업 선택 또는 직접 마스크·방향 지정
→ POST /api/v1/edit-jobs
→ queued/processing/validating 폴링
→ 후보 다운로드 또는 로컬 보정 유지
```

현재 P2가 구현한 항목:

- `rescue/analyze`가 사진·현재 스타일·레퍼런스 구도에 기반한 최대 3개 추천을 반환한다.
- 추천만으로는 edit job이 생성되지 않는다. 사용자가 작업을 선택해야 생성 API를 호출한다.
- 기존 edit-job Android API의 폐기 표시를 제거하고, 생성·폴링·다운로드 계약을 복구했다.
- `RescueRepository`와 `RescueController`가 `Idle → Analyzing → Recommendations → Editing → Submitting → Polling → Candidates/LocalFallback` 상태를 제공한다.
- `ContentScale.Fit`의 실제 사진 영역을 기준으로 브러시·다각형 좌표를 정규화하는 `RescueCoordinateMapper`를 제공한다. 레터박스 터치는 무시한다.
- LaMa 결과의 얼굴 수·임베딩·색상 차이는 품질 경고로 기록하며 단독으로 후보를 숨기지 않는다. 입력 별칭·디코드·크기·원본 픽셀 보존은 하드 검증이다.
- outpaint는 방향별 확장 캔버스를 만들고 생성 결과에 원본 내부 픽셀을 다시 합성한다. ComfyUI workflow가 없으면 `ProviderNotReady`로 안전하게 숨겨진다.
- 원본은 덮어쓰지 않으며 다운로드 후보는 기존 `edit_results_local` 및 편집 스택 기록 경로를 사용한다.

## P1 연결 계약

P1은 화면·디자인을 소유한다. 다음 호출만 연결하면 된다.

- `AppContainer.rescueController.state` 수집
- 사진 선택 후 `analyze(file, captureRef, styleParams, referenceComposition)` 호출
- 추천 카드 선택 후 `choose(operation)` 호출
- 직접 지우기·여백 조작 결과를 `choose(operation)`으로 전달
- 사용자가 실행한 경우에만 `submit(...)` 호출
- `Recommendations`, `Candidates`, `LocalFallback` 상태를 기존 결과 화면에 표시

P1 화면에서 생성 전 자동 업로드, 기술 점수 노출, 원본 덮어쓰기는 하지 않는다.

## CAMP-2 운영 상태

- 2026-07-29에 `POST /api/v1/rescue/analyze`와 GPS EXIF 선제 제거를 포함한 서버를
  CAMP-2에 재배포했다. 공개 OpenAPI와 실제 스모크 요청에서 라우트 응답을 확인했다.
- 공유 분석기는 FastAPI 시작 단계에서 워밍업한다. 모델 초기화가 끝난 뒤에만 요청을
  받으므로, 첫 사용자가 모델 로딩 대기 때문에 Android 네트워크 제한을 넘지 않는다.
- `gamdo-server.service`, `gamdo-worker.service`는 모두 active이며, 확인 시점
  `storage/inputs`의 미purge 업로드 파일은 0개였다.
- LaMa workflow는 기존 설정을 사용한다.
- FLUX.1 Fill은 서버 코드와 환경 변수 계약을 추가했지만, CAMP-2에는 실제 모델과
  `GAMDO_COMFYUI_OUTPAINT_WORKFLOW`가 없다. 따라서 API는 현재 `capabilities.outpaint=false`를
  반환하며 P1은 여백 확장 추천·실행 UI를 숨겨야 한다.
- 2026-07-29 edit-job 실경로 검증에서 실제 이미지와 명시적 `remove_objects` 마스크로
  `processing → done`을 확인했다. 최종 `fail_reason`은 `null`이고 LaMa 후보 2개가 모두
  `validation=passed`였으며, ComfyUI 두 prompt도 정상 완료했다. 별도 직접 prompt에서 발생한
  image/mask 크기 불일치 오류는 DB edit-job과 연결되지 않은 수동 테스트 오류로 분리한다.
- B 기기 EfficientDet GPU 채택은 현재 ADB 기기 미연결로 확인하지 못했다. 연결 후
  `adb logcat -d -s EfficientDet:*`에서 `gpuUpgrade=ADOPTED`가 확인될 때까지 미검증이다.
- 모델·workflow가 준비된 뒤 진단 p95 5초, LaMa p95 10초, FLUX p95 30초를 측정한다.

## 후속 개선

- CAMP-2에서 실제 FLUX workflow 설치·워밍업·결과 품질 측정
- P1 결과 화면의 추천 카드·직접 수정 UI 연결
- 사용자의 자연어 입력을 허용된 작업 목록으로 변환하는 LLM 보조 인터페이스 검토

LLM은 현재 기본 경로에 포함하지 않으며 생성 작업을 자동 실행하거나 마스크를 자동 확정하지 않는다.
