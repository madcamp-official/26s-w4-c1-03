# P2 테스트 가이드 (2026-07-25 실측)

P2가 만든 것(순수 Kotlin 모듈 4개 + FastAPI 서버)을 **직접 눈으로 확인하는 방법**과, 이 문서를 쓰면서 실제로 측정한 값·확인된 공백을 정리한다. 계획 문서는 `P2_Plan_1.md`, 이 문서는 그 검증 절차다.

## 0. 준비

```powershell
# Android: JAVA_HOME은 매번 지정 (PATH 기본 java는 JDK 19 → AGP 8.7 범위 밖)
$env:JAVA_HOME = "C:\Program Files\Android\Android Studio\jbr"

# 서버: 가상환경이 gamdo-server/.venv 에 이미 있음
cd gamdo-server
.\.venv\Scripts\python.exe -V   # 3.11.1
```


디버그 빌드에서는 화면 좌상단에 P2 값이 그대로 뜬다 (상단 "내 감도 적용 중" 칩을 누르면 HUD 토글).

```
119.1ms · 9fps · drop 0%
얼굴 0 · 포즈 0
수평 96.3° · 기울기 88.9° · 흔들림 0.000
preset: 깔끔한 소셜 (1/6) ▸          ← 탭하면 프리셋 6종 순환 (디버그 빌드 전용)
aligned=false visible=false · IoU 0.00 · match 0.35
area 0.00 · headroom 0.00 · margins 0.00/0.00
luma 0.40 · poseConf 0.00 · backlight=false lowLight=false
```

확인 순서:

1. 사람을 프레임에 넣어 `poseConf`가 0.3 이상으로 올라가면 `visible=true`가 되고 목표 프레임·실루엣이 그려진다.
2. `preset:` 칩을 눌러 6종을 돌리면 목표 프레임의 위치·크기와 `match` 값이 프리셋마다 달라져야 한다(하드코딩이 아니라 `presets.json`에서 온 값임을 이렇게 확인한다).
3. `area`/`headroom`/`margins`가 0~1을 벗어나지 않는지, 걸을 때 목표 프레임이 튀지 않는지 본다. 튀면 `assets/guide_config.json`의 `smoothingWindow`·`recomputeMovementThreshold`를 올린다(§3-2 현장 튜닝).
4. `aligned=true`가 되면 오버레이가 흰색 → 세이지로 바뀐다. **아래 4-1 참고: 현재 임계값으로는 거의 트리거되지 않는다.**

측정된 프레임 비용: 얼굴+포즈 ML Kit 동시 실행에서 프레임당 119~123ms, 9fps (`targetFps = 12` 미달, drop 0%).

## 4. 확인된 공백 — 현재 상태와 잔여 판정

계획서 §0.6은 "구현·자동 테스트 통과"까지를 완료로 표시한다. 아래는 이번 검증에서 **값이 실제로 흐르지 않는다**고 확인한 지점이다.

### 4-1. 튜닝/알고리즘 (P2 소유)

1. **`aligned`가 사실상 트리거되지 않는다.** `alignedIouThreshold = 0.7`인데, 목표 프레임은 `subjectScaleRange` 중앙값(0.35~0.55 → 높이 0.45)으로 만들어지고 전신 인물의 포즈 박스 높이는 0.7~0.9다. 정면 중앙 인물에서도 IoU 최댓값이 0.39(§1 덤프)라 색 전환이 일어나지 않는다. 임계값을 낮출지, 목표 프레임을 인물 박스 크기에 맞게 투영할지 결정이 필요하다.
2. **`MatchScoreCalculator`가 파이프라인에 연결돼 있지 않다.** `AlignmentEngine.metrics().matchScore`에는 IoU가 들어간다. 로드맵 §4.2 가중식은 테스트만 통과한 상태이고, 지금은 디버그 HUD에서만 계산해 표시한다. KPI 로그로 남길 값을 둘 중 무엇으로 할지 정해야 한다.
3. **`ProfileEngine` 추천 거리 정규화는 해결됐다.** `colorTemperature`를 2000K 범위로 정규화하고 나머지 차원은 0..1 범위로 제한했다. Kelvin이 다른 차원을 압도하지 않는 회귀 테스트를 추가했다.
4. **`PresetProfile` 매핑이 정의돼 있지 않다.** `ProfileEngine`은 카드 특성 공간(`framing`, `brightness`, `sharpness`, `candidness`)과 비교하는데 `presets.json`에는 대응 필드가 없다. 지금은 `P2ValueDumpTest`가 임시 근사 매핑을 들고 있다(그 사실을 주석에 명시). 정식 매핑표가 필요하다.
5. **`ProblemDiagnoser`의 UNDEREXPOSED value가 항상 0이다.** `min(brightnessMean, shadowClipRatio)`인데 어댑터가 `shadowClipRatio`를 주지 않으면 0으로 고정된다(실측: 어두운 사진 → `UNDEREXPOSED(MEDIUM, value=0.00)`). severity 계산은 정상이나 보고 값이 무의미하다.
6. **레퍼런스 분석의 인물 정보는 휴리스틱이다.** `peopleCount`/`subjects`는 피부색 픽셀 bbox이고 `horizon = 0.5`, `tilt = 0.0`, `cameraHeight = "chest_level"`은 상수다(§2-3 MediaPipe 미도입). 팔레트·색온도·히스토그램·노출 보정치는 실측값이다.

### 4-2. 앱 통합 (A와 합의 필요)

7. **앱 네트워크 클라이언트는 구현됐다.** `GamdoApiClient`가 `/api/v1` 경로, `X-Device-Id`, multipart 업로드, 상태 폴링, 결과 다운로드를 담당하며 CAMP-2 실기기 왕복까지 확인했다.
8. **`ProfileEngine` + `cards.json`은 온보딩에 연결됐다.** 카드 이미지·메타를 읽어 선택값을 저장하고, 추천 프리셋을 카메라 기본 스타일과 결과 기본 필터에 반영한다. 단, 현재 카드 에셋은 라이선스 증빙 전 데모 전용이다.
9. **`ProblemDiagnoser` 결과 화면 연결을 실기기에서 확인했다.** Bitmap 샘플에서 밝기·클리핑·라플라시안 분산을 추출해 자연어 진단 칩을 만들며, JVM/Debug APK 빌드를 통과했다. 어두운 테스트 사진에서 `조금 어두워요`·`선명도를 확인해보세요` 표시를 화면 캡처로 확인했고, 원본 로딩도 정상이다.
10. **`backlightFlag` 입력 경로를 연결했다.** 카메라 Y 평면을 한 번 순회하며 전체·얼굴·비얼굴 배경 밝기를 샘플링하고, ML Kit의 upright 얼굴 좌표를 회전 보정해 `BrightnessSample`에 전달한다. JVM 테스트와 APK 빌드는 통과했으며, 실제 역광 장면에서의 임계값 판정은 실제 사진·실기기 시각 검증 후 확정한다.
11. **프리셋 선택 UI는 카메라 스타일 칩으로 연결됐다.** 현재는 확정된 간결한 카메라 홈 구조에 맞춰 HUD/스타일 칩으로 제공되며, 별도 탐색 화면은 만들지 않는다.
12. **카드·프리셋 썸네일 파일은 번들에 존재한다.** 카드 16개와 프리셋 6개가 APK에 포함됐지만, 카드 출처·라이선스 증빙이 없어 정식 배포 승인은 보류다. 상세 기록은 `docs/감도_카드_에셋_라이선스_기록.md`를 참조한다.

### 4-3. 환경

13. **기기 → PC 일반 네트워크는 미확인이다.** 기기와 PC 서브넷이 달라 일반 Wi-Fi 경로는 보장하지 않는다. 개발·데모에서는 SSH 터널과 `adb reverse` 경로를 사용하며, 핫스팟 리허설은 별도 대기다.

    ```powershell
    & "C:\android-sdk\platform-tools\adb.exe" reverse tcp:8000 tcp:8000
    # 이후 앱에서 base URL은 http://127.0.0.1:8000
    ```

14. **GPU·ComfyUI·LaMa·InsightFace는 CAMP-2에 배포됐다.** 실제 사진·명시적 마스크 요청에서 `done`, 후보 2개, `validation=passed`, 결과 PNG HTTP 200을 확인했다. 공급자 실패·얼굴 보호 마스크에서는 기본 보정 fallback을 유지한다. 실제 인물 5쌍 캘리브레이션과 큐레이션 품질 판정은 아직 대기다.

15. **서버 오류 계약 테스트를 보강했다.** 잘못된 `operations` JSON, `remove_objects` 마스크 누락, 비이미지 업로드가 각각 `invalid_operations`, `mask_required`, `unsupported_image`로 반환되고 입력 파일이 저장되지 않는지 검증한다. 서버 테스트는 현재 28개 통과(기존 경고 2개는 외부 라이브러리 deprecation)다.
