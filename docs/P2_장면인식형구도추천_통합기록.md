# P2 장면 인식형 구도 추천 통합 기록

## 기록일

2026-07-27

## 2차 구현 기록 — 장면 맞춤 레이아웃 가이드

기존 `SceneProposalEngine`이 목표 프레임 위치만 바꾸던 한계를 보완했다.

- `SceneLayoutGuideEngine` 추가
  - `STATIC`: 피사체 미검출·낮은 신뢰도. 정적 프레임과 `피사체를 화면에 보여주세요` 안내
  - `DETECTING`: 피사체는 보이지만 신뢰도가 낮음. 감지 박스와 `피사체를 잠시 유지해주세요` 안내
  - `CONFIDENT`: 피사체 윤곽을 추천 구도 안으로 투영한 고스트 가이드 표시
- 인물은 포즈 랜드마크의 convex hull을 사용하고, 일반 물체는 감지 바운딩 박스를 사용한다.
- 기존 목표 브래킷과 세이지 색상 전환은 유지하며, 새 윤곽은 기존 오버레이 위에 기능적으로만 추가했다.
- 요청에 따라 안내 문구를 추가했으므로, 기존 D2의 텍스트 안내 금지 결정은 이 기능 범위에서 오너 요청으로 예외 처리했다.

## 3차 구현 기록 — True Segmentation

- 공식 ML Kit Subject Segmentation(`play-services-mlkit-subject-segmentation:16.0.0-beta1`)을 카메라 분석 경로에 추가했다.
- 전경 confidence mask를 32×32 저해상도 grid로 축약해 실제 전경 경계의 좌·우 윤곽과 normalized bounds만 전달한다. 원본 마스크와 이미지는 저장하지 않는다.
- 모델 초기화·다운로드 중 또는 180ms 초과/실패 시 기존 ML Kit object bounding box를 유지한다.
- 세그멘테이션은 6프레임마다 갱신하고 마지막 유효 결과를 재사용해 실시간 분석 부하를 제한한다.
- `SceneProposalEngine → SceneLayoutGuideEngine`에서 세그멘테이션 윤곽을 포즈 점·물체 박스보다 우선해 추천 구도 안으로 투영한다.

## 수정 범위

P2에서 구현한 장면 인식형 구도 추천을 기존 카메라 분석 흐름에 연결했다.

이번 변경은 P1 화면의 레이아웃·색상·타이포그래피·컴포넌트 배치를 수정하지 않고, 다음 기능 영역만 수정했다.

- `CameraScreen`: 얼굴·포즈 detector에 물체 detector와 throttling 경로 추가
- `CameraScreen`: Y 평면 구조 신호(`rowLuminance`, `sideEdgeDensity`) 전달
- `CameraViewModel`: `SceneGuideCoordinator` 호출 및 장면별 `StyleTarget` 적용
- `CameraViewModel`: 물체 피사체 박스를 `AlignmentEngine` 정렬 입력으로 전달
- `CameraViewModel`: 분석 디버그 라벨에 물체 검출 개수 추가

## 런타임 흐름

```text
CameraX ImageProxy

```

## 4차 구현 기록 — 인식 신뢰도 개선

- ML Kit Object Detection에서 분류 라벨이 없을 때 임의로 넣던 `0.5` 신뢰도를 제거했다. 라벨이 없는 박스는 `classificationConfidence=null`, 내부 분류 신뢰도 `0`으로 남긴다.
- 세그멘테이션이 있으면 물체 종류를 확정하지 않고 윤곽만 사용하며, 라벨이 없는 박스를 잘못된 물체 종류로 사용자에게 확정하지 않는다.
- Debug HUD에 실제 물체 라벨·분류 신뢰도·세그멘테이션 사용 여부(`seg=on/off`)를 추가했다.
- 전용 6종 분류 모델은 학습용 이미지와 모델 파일이 필요하므로 이번 변경에 임의의 외부 모델을 넣지 않고 다음 단계로 남겼다.
- SM-S928N의 분석 FPS·프리뷰 지연·발열
- 카메라 권한·렌즈 전환·화면 재구성 후 detector lifecycle

## 제품 규칙 준수

- 텍스트 지시 문구·화살표·일치도 점수·자동 촬영을 추가하지 않았다.
- 생성된 구도 후보 점수는 내부 판단에만 사용한다.
- 물체 검출 실패 시 고정 레이아웃을 임의로 표시하지 않고 탐색 상태를 유지한다. 고정 변형 자동 선택은 실기기 검증에서 인식률 저하가 확인된 뒤 도입할 후속 대응이다.

## 5차 기록 — 제품 계약 확정: 장면 기반 고정 레이아웃

2026-07-27 사용자 확인으로 다음 동작을 제품 계약으로 확정했다.

- 감도는 사용자가 먼저 대략적인 구도를 잡은 뒤 참고하는 보조 오버레이다. 카메라가 물체를 따라 움직이거나 자동 촬영하지 않는다.
- 카메라 시작 직후에는 기본 카메라 화면만 표시한다. 물체가 안정적으로 검출된 순간부터 고정 레이아웃을 표시하며, 분석 중에는 방해되지 않는 로딩 표시만 허용한다.
- 안정 인식은 최근 5프레임 중 3프레임 이상 같은 객체가 검출되는 것으로 정의한다. tracking ID를 우선하고, ID가 없으면 위치·중심점·IoU로 동일 객체를 연결한다. 시간 제한은 두지 않으며 조건을 만족할 때까지 탐색한다.
- 물체 종류 라벨은 필수가 아니다. 유효한 객체 박스가 안정적으로 유지되면 라벨이 없어도 일반 슬롯을 만든다. 세그멘테이션 마스크는 외곽선 정밀화용이며, 마스크 실패만으로 슬롯을 숨기지 않는다.
- 슬롯은 최대 4개다. 5개 이상이면 크고 중앙에 가까운 주요 물체를 우선한다. 하나의 박스로 합쳐진 물체는 임의로 나누지 않고 하나의 슬롯으로 처리한다.
- 얼굴 박스가 있으면 얼굴로 인정하고 인물 슬롯과 물체 슬롯을 함께 표시한다. 얼굴이 없으면 물체 슬롯만 표시한다.
- 레이아웃은 최초 안정 장면에서 확정한 뒤 고정한다. 물체가 잠시 사라져도 재탐색하지 않는다. 재탐색은 추후 전용 버튼을 누르거나 카메라를 껐다 켤 때만 수행한다.
- 슬롯의 비어 있음·채워짐 상태, 정렬 점수, 색상 변화는 사용자에게 표시하지 않는다. 사용자가 직접 맞았다고 판단해 셔터를 누른다.
- 슬롯은 고정된 반투명 레이아웃이다. 인물은 실루엣, 일반 물체는 둥근 사각형, 특화 장면은 간단한 컵·접시 형태를 사용한다. 실제 감지 외곽선을 프레임마다 따라 그리지 않는다.
- 1차로 물체 개수·종류·배치와 감도 스타일을 결합해 레이아웃을 선택한다. 장면이 슬롯 수·레이아웃 종류를 정하고, 스타일이 여백·크기·좌우 배치·분위기를 조정한다.
- 1차 구현에서는 객체가 안정적으로 인식될 때까지 탐색 상태를 유지한다. 객체 검출 자체가 실패하면 레이아웃을 표시하지 않는다.
- 실기기 검증에서 인식률이 너무 낮다고 판정될 경우에만 후속 변경으로 사전 검증된 고정 레이아웃 변형 중 하나를 자동 선택한다. 이는 현재 구현의 런타임 fallback이 아니다.

## 6차 기록 — 레이아웃 선택 버튼과 자동 탐색 제어

- 기본 모드는 자동 레이아웃 탐색이다. 사용자가 별도 조작하지 않으면 객체가 안정적으로 인식될 때까지 탐색하고, 확정된 레이아웃을 고정한다.
- 사용자는 우측 상단 레이아웃 버튼에서 고정 레이아웃 중 하나를 선택할 수 있다. 선택한 고정 레이아웃은 현재 자동 레이아웃을 즉시 대체하며, 촬영 중에도 다른 고정 레이아웃으로 변경할 수 있다.
- `재탐색`은 고정 레이아웃을 해제하고 자동 레이아웃 탐색을 다시 시작하는 동작이다. 이는 자동 탐색 실패 시 임의 변형을 고르는 fallback과 다르다.
- 과거에 사용한 “변형 선택”이라는 표현은 실기기 검증에서 인식률 저하가 확인될 때 도입할 후속 fallback을 뜻한다. 사용자가 레이아웃 버튼으로 고정 레이아웃을 직접 고르는 기능과는 별개이며, 현재 1차 구현에는 fallback으로 적용하지 않는다.
- 레이아웃 버튼의 위치·목록 구성·선택 UI·재탐색 버튼의 시각적 표현은 P1과 별도 계약한다. 본 문서는 동작 계약만 정의한다.
- 고정 레이아웃 선택은 현재 카메라 세션에만 유효하다. 카메라 화면을 벗어나 앱을 종료하거나 갤러리·다른 화면으로 이동하면 선택을 폐기한다. 다음 카메라 진입과 앱 재실행의 기본값은 항상 자동 탐색이며, 세션 간 레이아웃 선택은 저장하지 않는다.

## 7차 기록 — 촬영 후 처리 우선순위

- 감도의 핵심은 촬영 전 구도 가이드다. 사용자는 고정 레이아웃을 참고해 직접 셔터를 누른다.
- 촬영 후에는 오버레이를 사진에 합성하거나 자동 재배치하지 않고, 실제 촬영 원본을 먼저 보존·표시한다.
- 선택된 감도 스타일의 색감 보정은 촬영 후 로컬에서 적용한다. 사용자는 원본과 보정 결과를 비교하고 강도를 조절하거나 보정본을 새 파일로 저장한다.
- 객체 제거·여백 확장 등 GPU 생성 기능은 사용자가 `사진 살리기`를 명시적으로 선택한 경우에만 실행한다.

## 8차 기록 — 구도 가이드 성능·정확도 기준

- 물체가 계속 화면에 보이는 경우 최초 레이아웃은 2초 이내 표시한다.
- 기준 기기에서 객체 분석 평균 8FPS 이상을 목표로 한다.
- 안정 확정 기준은 최근 5프레임 중 3프레임에서 같은 객체가 검출되는 것으로 유지한다.
- 객체 이름 분류 정확도는 핵심 수용 기준이 아니다. 분리된 주요 피사체 수와 위치를 안정적으로 슬롯에 반영하는지를 평가한다.
- 레이아웃 확정 전 순간적인 검출 누락은 다시 탐색한다. 레이아웃 확정 후에는 물체 검출 변동으로 레이아웃을 움직이지 않는다.

## 9차 기록 — 실시간 처리 위치 확정

- 얼굴·포즈·물체 감지, 피사체 수·위치 계산, 레이아웃 선택은 전부 온디바이스에서 수행한다.
- 실시간 카메라 프레임을 서버로 업로드하지 않으며, 인식률이 낮다고 서버 분석으로 자동 전환하지 않는다.
- 레퍼런스 사진 분석과 생성형 편집만 사용자의 명시적 선택 후 서버·GPU를 사용한다.

## 10차 기록 — 탐색 상태 표시 확정

- 객체가 없거나 최근 5프레임 중 3프레임 안정 조건을 아직 충족하지 못한 동안에는 작고 방해되지 않는 로딩 표시를 계속 노출한다.
- 레이아웃이 확정되면 로딩 표시를 숨긴다.
- 탐색 실패·대기 상태에서 행동을 지시하는 문구나 오류 메시지는 표시하지 않는다.
- 레이아웃이 없어도 사용자는 수동 셔터로 촬영할 수 있다.

## 11차 기록 — 서버·생성 실패 처리 확정

- 레퍼런스 분석 실패 시 기본 감도 스타일과 카메라 촬영을 계속 사용할 수 있다.
- GPU 생성 실패 시 원본을 보존하고 기본 로컬 보정 결과를 표시한다.
- 생성 실패를 오류 화면으로 노출하지 않으며, 결과가 없으면 생성 결과 트랙만 숨긴다.
- 네트워크가 없어도 촬영·기본 보정·저장은 가능하다.
- 서버 기능은 사용자가 다시 명시적으로 실행할 수 있다.

## 12차 기록 — 계약 기반 탐지·레이아웃 엔진 구현

2026-07-27 P2 브랜치 `codex/scene-layout-contract`에 다음을 구현했다.

- `ObjectDetectionBatch`로 실제 객체 추론 프레임과 캐시 프레임을 구분한다. 캐시 결과는 안정화 횟수에 중복 계산되지 않는다.
- `StableSceneTracker`가 tracking ID·IoU·중심 거리로 최대 4개 객체를 3/5 기준으로 안정화한다.
- 객체 라벨과 분할 마스크가 없어도 유효한 박스를 일반 레이아웃 후보로 사용한다. 분류 신뢰도는 특화 레이아웃 선택에만 사용한다.
- 얼굴 박스만으로 인물 슬롯을 만들며, 얼굴과 물체가 동시에 있으면 두 종류 슬롯을 결합한다.
- 일반 물체 1~4개용 단일·행·열·대각·삼각·2×2 템플릿과 기존 특화 5종을 제공한다.
- `GuideLayoutState.Searching`과 `GuideLayoutState.Fixed(AUTO|MANUAL)` 상태를 추가하고, 확정 후 템플릿이 탐지 결과를 따라가지 않도록 고정한다.
- `SceneGuideSessionController`에 수동 레이아웃 선택·재탐색·스타일 변경·세션 종료 연결 계약을 추가했다.
- 슬롯 채움 상태는 호환·KPI 용도로만 남기고 제품 상태 결정과 셔터 가능 여부에서 제거했다.
- `StyleTarget.backgroundRatioRange`를 레이아웃 변환에 연결해 스타일별 크기·여백·중심을 반영한다.
- DB 스키마와 P1 화면·디자인 파일은 변경하지 않았다. P1은 컨트롤러 상태를 연결해 탐색 로더와 균일한 슬롯 렌더링을 적용해야 한다.

자동 검증은 `:app:testDebugUnitTest` 389건 통과 기준이며, 실기기에서의 인식 품질·2초 내 표시·8FPS는 아직 미검증이다.
