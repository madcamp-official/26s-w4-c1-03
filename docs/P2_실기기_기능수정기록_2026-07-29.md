# P2 실기기 기능 수정 기록 — 탐지·상태·AI·성능

작성일: 2026-07-29  
기준 기기: SM-S928N  
문서 상태: 실기기 검증으로 확인된 P2 잔여 수정 영역  
담당: P2 탐지·순수 Kotlin 상태·서버·CAMP-2·성능

## 1. 목적과 경계

이 문서는 앱 데이터를 삭제하고 온보딩부터 직접 확인한 결과 중 P2가 수정하거나 검증해야 하는 항목을 P1 화면 요청과 분리해 기록한다. Compose 배치·버튼·디자인·CameraX 촬영 callback은 P1 문서에서 관리한다.

## 2. 최우선 P2 항목

### P2-B1. 빈 장면의 잘못된 확정 상태

실측:

```text
얼굴 0 · 포즈 0 · 물체 0[none]
layout=confident
fixed=none
visible=true
```

이 상태는 제품 계약과 모순된다. 객체·얼굴·수동·레퍼런스 레이아웃이 없다면 `Searching`이어야 한다.

수정 방향:

- `GuideLayoutState.Fixed`는 실제 template ID와 1개 이상의 유효 슬롯이 있을 때만 만들 수 있게 한다.
- `fixed=none`을 `confident`로 변환하는 호환 어댑터·기본 프리셋 경로를 찾는다.
- 빈 `StyleTarget`의 브래킷이 제품 슬롯처럼 전달되지 않게 한다.
- P1이 잘못 렌더하더라도 `Searching` 계약이 모호하지 않도록 상태 타입을 강화한다.

완료 기준:

- 빈 장면 30초 동안 임의 `Fixed`가 발생하지 않는다.
- 수동·레퍼런스·자동 장면 확정만 `Fixed`를 생성한다.

### P2-B2. 활성 레퍼런스와 결과 필터 상태 소실

실측 로그에는 `referenceApplied scope=BOTH`와 `activeReferenceRestored`가 기록됐지만 결과 화면에는 내 감도 항목이 없었다.

P2 수정·검증:

- `ReferenceRepository.activeReference`를 단일 영속 `StateFlow` 원천으로 유지한다.
- `ResultFilterStateHolder`가 활성 레퍼런스 변경을 즉시 수집하는지 확인한다.
- `ReferenceCreateState.Applied`, 시트 닫기, controller dispose가 활성 레퍼런스를 삭제하지 않게 한다.
- BOTH/COLOR일 때 기본 6종 + 내 감도 항목을 생성하고 COMPOSITION일 때 기본 6종만 유지한다.
- 미리보기 render 상태와 필터 item 목록 상태를 분리한다.
- 앱 재실행·결과 화면 재생성·앨범 재진입 회귀 테스트를 추가한다.

P1은 이 상태를 화면에서 구독·렌더링할 책임을 가진다.

### P2-B3. 온보딩 감도의 자동 색감 적용 계약

현재 온보딩 프로필은 카메라에서 `내 감도 적용 중`으로 표시되지만 결과 사진은 원본이 기본이다.

P2 수정 방향:

- 온보딩 추천 프리셋 또는 활성 레퍼런스에서 `ResolvedStyle.colorTargetOrNull()`을 결정한다.
- 사진 진입 시 `LocalEditor`가 계산할 기본 감도 결과를 명확한 상태로 제공한다.
- 우선순위를 `활성 레퍼런스 색감 > 세션 프리셋 > 온보딩 추천`으로 고정한다.
- P1이 기본 선택할 수 있도록 `recommendedDefaultFilterId`를 제공한다.
- 색감 생성 실패 시 원본을 반환하되 필터 상태 자체는 유지한다.

## 3. AI 3 추천·생성 경로

### P2-A1. 의미 없는 `local_style` 단일 추천

실기기에서는 진단 요청이 약 1.5초 안에 성공했지만 추천 한 개가 `내 감도로 정리하기`였고, 선택 후 “지금 보정만 그대로 둘게요”로 종료됐다. edit-job은 생성되지 않았다.

개선 방향:

- `local_style`은 네트워크 생성 작업이 아니라 즉시 로컬 보정 결과로 연결한다.
- 진단 응답이 local_style만 포함하면 서버 분석 화면을 한 단계 더 거치지 않게 한다.
- 현재 감도 기준으로 여백·구도·역광 진단이 실제 recommendation을 만드는지 샘플 세트로 검증한다.
- 추천 최대 3개와 서버 capability를 분리해, 추천되지 않아도 직접 수정에서는 준비된 작업을 선택할 수 있게 한다.
- 추천 이유는 기술 수치가 아니라 P1이 일상 문구로 표시할 수 있는 code로 제공한다.

### P2-A2. 생성 operation 실제 완료 검증

현재 실기기 흐름에서는 생성 operation까지 도달하지 못했다.

검증 대상:

- `remove_objects`: 명시적 마스크 → edit-job → 후보 다운로드
- `outpaint`: 방향·비율 → FLUX 후보 → 원본 내부 보존
- `viewpoint`: 방향·강도 → provider → 후보 검증
- `relight`: 조명 방향·강도 → provider → 후보 검증
- 모든 provider 실패 → `LocalFallback`

각 operation은 submit 1회, 상태 폴링, 후보 다운로드, 비파괴 저장까지 서버·Android 로그를 함께 확인한다. readiness가 false인 operation은 recommendation과 직접 수정 목록 모두에서 제외한다.

## 4. 객체 분석 성능

실측 범위:

- 분석 시간: 약 116~148ms
- 객체 분석: 약 6FPS
- 프레임 드롭: 30~41%
- 프리뷰: 약 15FPS
- 기준: 평균 8FPS 이상, 드롭 20% 이하

GPU delegate는 SM-S928N에서 `GL_INVALID_VALUE`로 실패하고 CPU로 폴백했다. 앱 중단은 없었지만 목표 성능에 미달한다.

개선 방향:

- GPU validation은 세션당 한 번만 시도하고 실패 뒤 재시도를 막는다.
- CPU 경로는 최신 프레임 하나만 처리한다.
- 레이아웃이 `Fixed`가 되면 객체 탐지를 중단하고 재탐색 때만 재개한다.
- 중앙 crop 재추론은 Searching이고 후보 0~1개일 때만 실행한다.
- ML Kit 얼굴·포즈와 EfficientDet 작업이 같은 프레임에서 불필요하게 중복 대기하지 않는지 계측한다.
- `analysisMs`, 실제 inference FPS, dropped frame을 단계별로 분리한다.
- 입력 크기·탐지 주기는 `guide_config.json`으로 조정한다.

완료 기준:

- 기준 기기 평균 8FPS 이상
- 드롭 20% 이하
- 안정 장면 최초 레이아웃 2초 이내
- GPU 실패 상태에서도 CPU 촬영·앨범 이동에 체감 멈춤 없음

## 5. 객체 수·인물 장면 품질

이번 흐름에서는 빈 장면 상태를 확인했으며, 기존 실기기 테스트에서는 흩어진 물체와 겹친 물체의 수가 불안정했다. 다음 회귀를 유지한다.

- 중앙 주요 피사체 1~4개와 슬롯 수 일치
- 같은 물체의 다중 라벨 박스 제거
- 겹쳤지만 독립적으로 반복 검출된 물체는 별도 유지
- 한 박스로만 검출된 덩어리를 임의 분리하지 않음
- 배경 인물은 제외하고 중앙 주 인물 최대 한 명 선택
- 얼굴과 물체가 함께 있으면 인물·물체 슬롯 함께 생성
- 장면 확정 후 재탐색 전까지 슬롯 고정

## 6. P1에 제공해야 할 상태 계약

P2는 화면이 임시 내부값을 추론하지 않도록 다음을 명확히 제공한다.

- `GuideLayoutState.Searching | Fixed(template, source)`
- 실제 template이 없는 `Fixed` 금지
- `ResultFilterState.items`, `selectedId`, `activeReference`, `renderState`
- `recommendedDefaultFilterId`
- `RescueState`와 operation별 readiness/capability
- 생성 진행 단계와 후보·fallback 상태
- 실시간 계측은 Debug 전용 별도 stream

## 7. P2 검증 체크리스트

- [ ] 객체 0·얼굴 0에서 `Searching` 유지
- [ ] 실제 슬롯 없는 `Fixed/confident` 상태 제거
- [ ] 활성 레퍼런스 적용 뒤 ResultFilterState에 내 감도 유지
- [ ] 화면 재생성·앱 재실행 뒤 내 감도 복원
- [ ] 온보딩 감도가 기본 로컬 보정 결과로 제공됨
- [ ] local_style 추천이 불필요한 서버 생성 흐름을 만들지 않음
- [ ] 준비된 AI 3 operation별 edit-job 완료
- [ ] readiness false operation 숨김
- [ ] CPU 평균 8FPS·드롭 20% 이하
