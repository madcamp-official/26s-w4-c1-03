# P1 요청 — 온디바이스 인식 결과와 구도 가이드 통합 수정

> 기준 main: `5b465ed`
> 목적: P1이 아래 현상을 직접 재현하고, P1 소유 화면·CameraX·Compose 연결 영역의 해결 방안을 독자적으로 수립해 구현한다.
> 원칙: P2의 탐지 모델 내부를 임의로 수정하지 않는다. P1은 전달된 상태·마크·슬롯을 누락하거나 다른 의미로 재가공하지 않는다.

## 현재 main에서 확인된 사실

P1 실기기 검증 회신에 따르면 카메라 전환 중 발생하던 EGL 크래시는 다음 수정으로 해결됐다.

- `SurfaceOutput` 해제 콜백을 GL 스레드로 이동
- EGL surface 파괴 전 pbuffer를 current로 복귀
- 은퇴한 출력 콜백의 항등 가드
- surface 생성 실패 시 프로세스 종료 대신 detach

전환 재현은 수정 전 13/13 크래시에서 수정 후 15/15 무크래시로 개선됐다. 이 부분은 P1의 후속 실기기 검증 대상으로 유지한다.

반면 아래 문제는 아직 사용자 경험상 해결되지 않았다.

1. 올가미 안의 분리된 두 객체가 링 하나로 표시됨
2. 상황 우선 `GuideMark`와 고정 레이아웃 `LayoutSlot`의 시각 체계가 혼재함
3. 수동 인물 레이아웃을 선택해도 사용자가 무엇을 맞춰야 하는지 알기 어려움
4. 상황 칩을 선택해도 화면 변화가 거의 없어 기능 의미가 전달되지 않음
5. QR 진입·공유 레이아웃 미리보기 흐름이 화면에서 명확하지 않음

## P1이 먼저 수립할 구현 계획

P1은 코드를 수정하기 전에 다음을 포함한 짧은 구현 계획을 작성해 본 문서 또는 별도 회신 문서에 추가한다.

- 각 문제의 재현 단계와 성공 기준
- 실제 구독하는 상태 Flow와 화면 컴포넌트
- `GuideMark`와 `LayoutSlot` 중 어떤 계약을 제품 카메라의 단일 표시 경로로 사용할지
- 기존 P1 디자인을 유지하면서 충돌을 해결할 컴포넌트·레이어 순서
- 수동 프레임 선택 직후 상태가 즉시 보이는지 검증할 방법
- `Searching`, `Fixed`, `Manual`, `Polygon` 상태별 화면 표시 규칙
- P2가 반환한 객체 수를 UI에서 줄이거나 재분류하지 않는 보장
- 실기기 검증 항목과 회귀 위험

계획 확정 후 P1은 해당 소유 영역을 직접 구현하고, 기능별 커밋을 상세 본문과 함께 main에 반영한다.

## 1. GuideMark와 LayoutSlot 표시 체계 통합

### 현재 문제

`CameraOverlay`는 `guideMarks != null`이면 `LayoutSlot`을 그리지 않고 `GuideMark.SubjectDot`을 우선한다. 따라서 올가미 결과가 두 객체여도 P2가 `GuideMark`를 하나만 반환하면 화면에는 링 하나만 보인다. 반대로 마크가 없을 때는 `SlotRenderStyle`에 따라 사람 실루엣·인물 브래킷·객체 코너 브래킷이 표시된다.

사용자에게는 다음 두 표현이 같은 “구도 가이드”로 보이므로, 상태에 따라 네모와 원이 번갈아 나타나는 현상이 혼란스럽다.

### P1 요구사항

- P2가 반환한 `GuideMark` 또는 `LayoutSlot`을 임의로 합치거나 첫 항목만 취하지 않는다.
- `GuideMark.SubjectDot`의 개수는 반환된 안정 객체 수와 동일하게 유지한다.
- `GuideMark` 경로와 `LayoutSlot` 경로 중 제품에서 사용할 단일 시각 언어를 P1이 선정하고 이유를 문서화한다.
- 객체는 동일한 점/링 표현으로 통일하거나, 슬롯 브래킷을 쓸 경우에도 객체마다 같은 규칙으로 표시한다.
- 인물 표현은 객체 링과 혼동되지 않도록 고정 실루엣 또는 명확한 인물 브래킷 하나로 통일한다.
- `GuideMark`가 존재한다는 이유로 고정 슬롯이 사라져 사용자에게 다른 레이아웃처럼 보이지 않게 한다.
- raw box, label, confidence, track ID는 계속 표시하지 않는다.

### 완료 기준

- 동일한 장면에서 자동·탭·올가미·수동 선택을 전환해도 가이드 표현 규칙이 일관된다.
- P2가 객체 2개를 반환하면 화면에도 객체 가이드 2개가 보인다.
- 인물 1명과 객체 2개면 인물 1개 + 객체 2개가 동시에 보인다.
- 가이드가 바뀌는 경우에는 원인이 모드/레이아웃 변경으로 설명 가능해야 하며, 단순 렌더 경로에 따라 모양이 바뀌지 않는다.

## 2. 수동 인물 레이아웃 연결

### 현재 문제

`person_full_center_v2`, `person_full_offset_v2`, `person_full_relaxed_v3`, `person_full_walking_v3`, `person_upper_v2`, `person_seated_v2` 템플릿과 `resolve()` 결과는 존재한다. 그러나 수동 선택은 `pendingGuideWork`를 통해 분석 스레드에서 지연 적용되고, 오버레이는 `layoutState`와 `layoutGuide.fixedLayout` 두 상태를 함께 참조한다.

사용자 입장에서는 선택 후 즉시 어떤 가이드가 활성화됐는지 알 수 없고, 전신 중앙/비대칭/자연스러운 흐름의 실질적 차이도 표시되지 않는다.

### P1 요구사항

- 수동 레이아웃을 누른 즉시 선택 상태를 UI에 반영한다. 분석 스레드 지연이 있어도 버튼 선택 상태와 미리보기는 먼저 바뀌어야 한다.
- `GuideLayoutState.Fixed(source=MANUAL)`와 실제 오버레이 입력이 동일한 template ID를 가리키는지 보장한다.
- `layoutState`만 갱신되고 `layoutGuide.fixedLayout`이 비어 있는 중간 상태를 제품 화면에 노출하지 않는다.
- 각 인물 프레임의 차이는 가이드 미리보기에서 읽혀야 한다.
  - 전신 중앙: 중앙·대칭형
  - 전신 비대칭: 좌우 여백이 다른 인물 영역
  - 자연스러운 흐름: 중앙에서 약간 벗어난 인물 영역
  - 리드 룸: 진행 방향 쪽 여백
  - 상반신: 머리·어깨 중심 영역
  - 앉은 인물: 하단 좌석 영역 포함
- 사용자가 맞춰야 하는 것은 “사람을 이 영역 안에 놓는 것”으로 단순화한다. 포즈 추론·점수·문구·자동 촬영은 추가하지 않는다.
- 수동 선택 후 객체 탐지를 중단하는 기존 계약을 유지하되, 수동 선택 자체가 탐색 대기 때문에 무효화되지 않게 한다.

### 완료 기준

- 인물 6개 수동 프레임을 각각 선택했을 때 1초 이내 선택 상태와 고정 가이드가 보인다.
- 카메라를 움직여도 수동 가이드 좌표가 객체를 따라 움직이지 않는다.
- 재탐색 또는 카메라 세션 종료 전까지 수동 템플릿 ID와 표시 형태가 바뀌지 않는다.

## 3. 상황 칩과 수동 프레임의 역할 분리

현재 상황 칩은 자동 탐색 우선순위를 바꾸고, 하단 프레임은 자동 탐색을 무시하고 즉시 고정한다. 그러나 화면에서 두 기능의 차이가 충분히 드러나지 않는다.

P1은 다음 중 하나를 스스로 결정하고 계획에 근거를 남긴다.

- 모델 readiness가 없는 동안 상황 칩을 숨기고 수동 프레임만 제공
- 상황 칩을 유지하되 선택 즉시 해당 모드의 고정 가이드 또는 명확한 모드 상태를 표시
- 상황 칩과 프레임 선택을 하나의 레이아웃 선택 흐름으로 통합

단순히 버튼을 남겨두고 아무 변화도 없는 상태는 완료로 인정하지 않는다. `AUTO`에서 모드 선택이 탐지 결과에 미치는 효과가 현재 모델 미탑재로 제한된다면, 사용자에게 무의미한 기능을 노출하지 않는 결정을 우선한다.

## 4. 올가미 표시 연결

올가미에서 객체가 하나로 합쳐지는 핵심 원인은 P2 탐지 단계로 분류되어 있다. P1은 이를 임의의 UI 필터로 보정하지 않는다.

다만 P1은 다음을 보장한다.

- P2 반환 목록의 1~4개를 모두 렌더링
- 올가미 완료 후 `Searching` 동안 작은 로딩만 표시
- 올가미 밖 객체를 UI에서 추가하지 않음
- 기존 고정 마크를 남겨 새 탐색 결과와 겹쳐 보이게 하지 않음
- scope revision 변경 시 이전 가이드가 남지 않음
- 한 객체만 반환됐을 때 이를 “두 객체 인식 완료”처럼 표현하지 않음

## 5. QR 진입 및 공유 레이아웃

P1은 카메라에 사용자가 직접 누르는 `나 찍어줘` 진입점을 추가한다.

- `Searching`: 버튼은 막지 않고 수동 프레임 선택 또는 공유 취소로 이어짐
- `Fixed`: 현재 template을 QR 정책으로 전달
- QR 생성 전 공유할 레이아웃 미리보기 표시
- QR 생성 후 만료 시각, 촬영 수, 받기/claim 상태 표시
- QR 웹은 P2가 전달한 고정 가이드만 표시하고, 촬영자에게 객체 분석·텍스트 지시를 요구하지 않음

서버 503/404를 UI에서 숨기지 말고 상태로 표시하되, 현재 main의 `/health`, shoot session, shoot upload 경로가 정상인지 P1이 실기기에서 확인한다.

## P1 최종 제출물

P1은 자체 계획 수립 후 다음을 제출한다.

1. 수정된 화면·CameraX 연결 코드
2. 수동 인물 6종과 자동/탭/올가미의 실기기 확인 기록
3. GuideMark/LayoutSlot 통합 결정을 반영한 P1 연결 문서
4. QR 진입부터 사진 수신까지의 시연 결과
5. 실패한 항목과 P2에 재요청할 탐지 계약

이번 요청은 P1이 디자인을 대신해주기를 기다리는 문서가 아니라, 현재 main의 상태 연결·렌더링·시연 흐름을 P1이 독자적으로 분석하고 해결하도록 위임하는 요청이다.
