# P1·P2 카메라 UX 및 AI 기능 개선 요구사항

문서 기준일: 2026-07-29  
문서 상태: **구현 전 요구사항 정리**  
대상: P1 디자인·화면 통합 담당, P2 탐지·구도·생성 AI 담당

## 1. 목적

현재 감도 앱은 기능과 디버그 정보가 촬영 화면에 직접 노출되어 일반 카메라 앱보다
복잡하게 보이고, 자동 구도·내 감도·AI 보정의 사용 방법도 직관적으로 드러나지 않는다.
이번 요구사항은 촬영 화면을 실제 카메라처럼 단순화하고, 필터와 프레임을 필요할 때만
펼쳐 쓰는 구조로 바꾸며, AI 보정의 중심을 객체 삭제보다 **생성형 구도 복구**로
확장하기 위한 후속 계약이다.

이 문서는 요구사항만 기록한다. 작성 시점에는 아래 항목의 구현을 시작하지 않았다.

## 2. P1 디자인·화면 요구사항

### P1-1. 촬영 화면 풀블리드 전환

- 우측 상단의 `4:5 / 1:1` 비율 전환 버튼을 제거한다.
- 촬영 프리뷰는 실제 카메라 앱처럼 화면의 촬영 가능 영역을 여백 없이 채운다.
- 상·하단 조작부는 불투명한 큰 패널로 프리뷰를 줄이지 않고, 프리뷰 위에 겹치는
  투명·반투명 오버레이 형태를 우선한다.
- 사용자가 본 프리뷰와 저장된 결과의 구도가 달라지지 않도록 프리뷰 크롭과 저장 크롭을
  같은 좌표 계약으로 맞춘다.
- 기존 4:5·1:1 전용 레이아웃 좌표는 풀블리드 화면 좌표로 변환하되, 피사체 슬롯이
  상·하단 조작부에 가려지지 않도록 안전 영역을 둔다.

완료 기준:

- 카메라 진입 직후 검은 여백이나 비율 선택 칩 없이 프리뷰가 화면을 채운다.
- 촬영 전 프레임에서 본 피사체 위치와 저장 사진의 위치가 실사용상 동일하다.
- 셔터·앨범·필터·프레임 버튼은 프리뷰를 불필요하게 축소하지 않는다.

### P1-2. 필터 패널 접힘 구조

- 하단의 6종 필터와 `내 감도` 목록을 카메라 진입 즉시 펼쳐놓지 않는다.
- 촬영 화면에는 기본적으로 **필터 버튼**만 표시한다.
- 필터 버튼을 탭하면 갤럭시 카메라의 필터 선택 방식처럼 하단 팝업 또는 확장 패널로
  필터 목록이 나타난다.
- 필터를 선택해도 패널과 필터 목록이 사라지지 않고 선택된 필터만 강조한다.
- 사용자가 패널 바깥을 탭하거나 필터 버튼을 다시 누르면 패널을 접는다.
- 필터 선택 결과는 패널을 접은 뒤에도 유지되며, 현재 적용 상태는 버튼의 작은 강조나
  썸네일로 확인할 수 있게 한다.

완료 기준:

- 카메라 기본 화면에서는 필터 썸네일 행이 보이지 않는다.
- 필터 버튼 한 번으로 목록을 열고 닫을 수 있다.
- 필터 선택·내 감도 적용 뒤에도 목록과 선택 상태가 유지된다.

### P1-3. 내 감도 오버레이 투명도 조절 UI 개선

- 촬영 화면에서 `내 감도`를 선택했을 때 나타나는 투명도 조절 버튼을 다시 디자인한다.
- 현재 버튼이 일반 기능 버튼처럼 보여 용도를 알기 어려우므로, 겹쳐진 사진·레이어 또는
  반투명 원형처럼 **투명도 조절임을 바로 이해할 수 있는 아이콘**을 사용한다.
- 버튼을 탭하면 0~60% 범위의 간결한 슬라이더 또는 팝업 조절기가 나타난다.
- 조절 중에는 현재 레퍼런스 오버레이가 즉시 바뀌어야 한다.
- `내 감도`가 비활성 상태일 때는 투명도 버튼을 숨기거나 비활성화한다.
- 기술 용어 대신 `겹쳐 보기` 또는 `사진 투명도`처럼 의미를 알 수 있는 접근성 라벨을
  제공한다.

완료 기준:

- 처음 보는 사용자도 버튼이 레퍼런스 사진의 투명도를 조절한다는 사실을 알 수 있다.
- 버튼과 조절기가 셔터·줌·프레임 가이드를 가리지 않는다.
- 내 감도를 해제하면 오버레이와 투명도 조절 UI가 함께 사라진다.

### P1-4. 전반적인 SNOW 카메라 계열 UX로 정리

SNOW의 브랜드 디자인을 복제하는 것이 아니라 다음 사용성 원칙을 참고한다.

- 사진 프리뷰가 화면의 주인공이 되는 풀스크린 구조
- 기본 화면에는 촬영에 꼭 필요한 버튼만 남기는 낮은 정보 밀도
- 부가 기능은 아이콘 탭 후 하단 패널로 펼치는 구조
- 큰 텍스트 칩과 불투명 카드 대신 가벼운 아이콘·반투명 배경·짧은 전환 애니메이션 사용
- 선택 상태는 세이지 강조색으로 구분하되 화면 전체를 세이지 패널로 채우지 않음
- 필터·프레임 패널의 열림/닫힘 방식과 높이, 썸네일 크기, 선택 강조 방식을 통일
- HUD·객체명·점수·분석 시간은 데모 디버그 모드에서만 표시하고 기본 화면에서는 숨김

P1은 위 원칙을 기준으로 카메라 화면 전체를 정리하되, 감도의 다크 차콜·세이지 브랜드와
촬영 전 구도 가이드라는 정체성은 유지한다.

## 3. P1·P2 공통 연결 요구사항: 기본 프레임 선택

자동 프레임 추천 외에 영뽀또처럼 사용자가 검증된 기본 프레임을 직접 고를 수 있어야 한다.
이 기능은 P2의 레이아웃 상태와 P1의 선택 패널을 함께 연결해야 한다.

### 사용자 흐름

```text
카메라 진입
→ 기본값은 자동 프레임 탐색
→ 프레임 모양 버튼 탭
→ 하단 프레임 패널 표시
→ 자동 / 기본 프레임 목록 중 선택
→ 선택 프레임을 즉시 고정해 촬영
```

### P1 담당

- 필터 버튼과 구분되는 **프레임 모양 버튼**을 촬영 화면에 배치한다.
- 버튼을 누르면 갤럭시 카메라의 필터 패널과 유사한 하단 팝업으로 프레임 목록을 표시한다.
- `자동`, 기본 프레임 썸네일, `재탐색`을 한 패널 안에서 이해할 수 있게 구성한다.
- 패널이 열린 상태에서도 셔터와 프리뷰를 사용할 수 있어야 한다.
- 선택된 프레임은 세이지 테두리 등 한 가지 방식으로만 강조한다.
- 필터 패널과 프레임 패널이 동시에 열리지 않게 한다.

### P2 담당

- 기존 `availableManualLayouts`, `selectManualLayout(templateId)`, `rescanLayout()` 계약을
  P1 패널에서 바로 사용할 수 있도록 유지·보강한다.
- 자동 탐색, 수동 프레임 고정, 재탐색 상태를 명확히 전달한다.
- 수동 프레임은 현재 카메라 세션에서만 유지하고 카메라 이탈 후 자동 탐색으로 초기화한다.
- 영뽀또식 기본 프레임 후보를 실제 촬영 구도 기법에 따라 재정리하고, 각 프레임의 슬롯
  좌표·비율·안전 여백을 제공한다.

## 4. P2 후속 구현 요구사항

아래 항목은 이번 문서에만 기록하며, 별도 구현 승인 전에는 작업을 시작하지 않는다.

### P2-1. 드래그 그물 선택 기반 물체 인식

현재 중앙 자동 탐색과 탭 주변 재탐색 외에, 사용자가 화면에서 직접 영역을 감싸 선택하는
방식을 추가한다.

권장 동작:

```text
프리뷰에서 길게 누르거나 선택 모드 진입
→ 손가락으로 원하는 물체 무리를 그물처럼 감쌈
→ 닫힌 선택 영역 생성
→ 영역 안의 객체만 다시 탐지·안정화
→ 객체 수와 배치에 맞는 고정 프레임 제공
```

- P1은 그물 경로·선택 영역·취소·재선택의 시각 피드백을 담당한다.
- P2는 화면 좌표를 분석 프레임의 정규화 다각형 ROI로 변환한다.
- 박스 중심이 선택 영역 안에 있거나 박스 면적의 일정 비율 이상이 겹치는 객체만 후보로
  사용한다.
- 선택 영역 밖의 배경 인물·모니터·케이블은 제외한다.
- 선택 영역에서 객체가 안정적으로 검출되지 않으면 임의 프레임을 만들지 않고 탐색을
  유지한다.
- 확정 뒤에는 기존 계약대로 재탐색 전까지 프레임을 고정한다.

완료 기준:

- 화면에 여러 물체가 있어도 사용자가 감싼 물체 무리만 슬롯 수에 반영된다.
- 세로·가로 프리뷰와 화면 크롭 상태에서 선택 좌표가 어긋나지 않는다.
- 드래그 선택, 탭 재탐색, 자동 탐색, 수동 프레임 선택이 서로 상태를 덮어쓰지 않는다.

### P2-2. 기본 프레임 카탈로그 제공

- 자동 인식과 별개로 즉시 사용할 수 있는 기본 촬영 프레임을 제공한다.
- 최소 후보는 1인 인물, 상반신 인물, 인물+사물, 물체 1개, 물체 2개 균형·대각,
  물체 3개 삼각·연속, 4개 2×2, 카페 테이블로 구성한다.
- 기본 프레임은 객체 인식 성공 여부와 무관하게 사용자가 직접 선택할 수 있다.
- 프레임 좌표는 풀블리드 프리뷰와 저장 결과에서 동일하게 보이도록 변환한다.
- P1이 썸네일을 만들 수 있도록 프레임 ID, 이름, 슬롯 역할, 미리보기용 간단한 벡터 정보를
  제공한다.

이 항목의 화면 요구사항은 §3의 P1·P2 공통 연결 계약을 따른다.

### P2-3. 인물용 포즈 레이아웃

현재 인물 인식은 얼굴 박스와 큰 인물 슬롯만 제공해 실제 자세를 잡는 데 도움이 부족하다.
인물 장면에는 머리·어깨·팔꿈치·손목·골반·무릎·발목을 점과 막대로 연결한 포즈 가이드를
제공한다.

- 얼굴과 주요 관절의 신뢰도가 충분하면 점·막대 형태의 고정 포즈 레이아웃을 표시한다.
- 포즈 가이드는 현재 인물의 관절을 계속 따라다니는 추적선이 아니라, 추천 자세를 나타내는
  고정 목표 레이아웃이다.
- 인물은 가이드의 점·막대 위치에 몸을 맞춘 뒤 사용자가 직접 촬영한다.
- 포즈 신뢰도가 낮거나 하체가 보이지 않으면 상반신용 레이아웃으로 축소한다.
- 얼굴만 검출되고 포즈를 얻지 못하면 기존 인물 실루엣 또는 기본 인물 프레임으로 폴백한다.
- 점수·방향 화살표·텍스트 자세 지시는 표시하지 않는다.

완료 기준:

- 전신과 상반신 장면에서 서로 다른 적절한 포즈 레이아웃이 선택된다.
- 여러 사람이 있어도 주요 인물 한 명의 레이아웃만 표시한다.
- 사용자가 움직여도 목표 포즈 레이아웃 자체는 재탐색 전까지 고정된다.

### P2-4. 앨범의 내 감도 필터 소실 버그

현재 앨범 사진에서 내 감도 필터를 추가한 뒤 선택하면 `내 감도` 항목 또는 필터 목록이
사라지는 문제가 재현된다. 이전 수정으로 완료 처리하지 않고 **실기기 재현 버그**로 다시 연다.

- 분석 완료 상태와 활성 레퍼런스 상태를 분리한다.
- `Applied → 화면 닫기`, 화면 재구성, 앨범 재진입이 활성 레퍼런스를 삭제하지 않게 한다.
- 필터 렌더링 실패나 미리보기 Bitmap `null`이 필터 목록의 표시 여부를 바꾸지 않게 한다.
- 내 감도 선택 뒤에도 기본 6종과 내 감도 슬롯을 그대로 유지한다.
- `구도만` 레퍼런스는 색감 적용 대상이 아니지만 기본 필터 목록은 그대로 유지한다.
- Debug 로그로 분석 성공, 활성화 저장, 복원, 색감 렌더 성공을 각각 구분한다.

완료 기준:

- 같은 실기기에서 내 감도 생성→적용→선택을 5회 반복해 목록 소실이 0회다.
- 카메라→앨범→결과→뒤로가기→재진입 후에도 활성 상태가 유지된다.
- 분석·색감 렌더 실패 시에도 기본 6종 필터는 사라지지 않는다.

### P2-5. AI 보정을 생성형 구도 복구 중심으로 전환

현재 객체 삭제 결과는 기능 가치와 생성 품질이 부족하다. AI 보정의 주 기능을 다음과 같은
**생성형 구도 수정**으로 재정의한다.

우선 기능:

1. 너무 확대된 사진의 화각 확장과 주변 장면 생성
2. 피사체가 치우치거나 잘린 사진의 좌·우·상·하 여백 생성
3. 제한된 범위의 카메라 위치·시점 변경에 가까운 구도 재생성
4. 역광 사진의 광원 방향·노출 균형·배경 밝기 재구성
5. 현재 감도 또는 내 레퍼런스 구도에 맞춘 후보 생성

제품 계약:

- 서버 진단은 사진의 잘림, 피사체 위치, 여백, 수평, 역광을 분석해 가능한 작업을 추천한다.
- 사용자가 작업과 강도를 선택하고 `실행`을 눌렀을 때만 GPU 생성을 시작한다.
- 단일 사진에서 실제 카메라 위치를 정확히 복원할 수는 없으므로, 결과는 물리적 복원이 아닌
  자연스러운 생성형 재구도로 취급한다.
- 원본 내부를 최대한 보존하고 새로 필요한 영역만 생성하는 아웃페인팅을 우선한다.
- 카메라 위치 변경이나 광원 재구성이 원본 내부까지 바꿔야 할 경우 후보에 `AI 생성 보완`
  표시를 유지한다.
- 얼굴 수·얼굴 유사도·주요 피사체 보존·경계 이음새·원본 내부 변화량을 검증한다.
- 품질 검증을 통과하지 못한 후보는 표시하지 않고 원본과 기본 로컬 보정을 유지한다.
- 객체 삭제는 주 기능이 아니라 `직접 수정 → 지우기`의 보조 기능으로 남긴다.

필요한 서버/GPU 작업:

- FLUX.1 Fill 또는 동급 아웃페인팅 workflow 실제 배치
- 화각 확장 방향·비율·캔버스·마스크 생성
- 제한적 시점 변경 모델 또는 workflow 후보 비교
- 역광/광원 재구성용 조건 입력과 품질 검증
- 원본·감도 구도·생성 후보의 비교 및 작업별 시간 측정

완료 기준:

- 너무 확대된 사진에서 5~15% 여백 확장 결과가 실제 후보로 반환된다.
- 피사체·얼굴을 보존하면서 감도 구도에 가까운 후보를 생성한다.
- 역광 보정은 단순 전체 밝기 증가가 아니라 피사체와 배경의 균형이 개선된다.
- 실패해도 원본·기본 보정·저장 흐름이 중단되지 않는다.

## 6. 권장 진행 순서

1. P1이 풀블리드 카메라 셸과 접히는 필터·프레임 패널 디자인을 확정한다.
2. P1·P2가 풀블리드 프리뷰 좌표와 저장 좌표 계약을 맞춘다.
3. P2가 기본 프레임 카탈로그와 프레임 선택 상태를 제공하고 P1이 패널에 연결한다.
4. P2가 내 감도 소실 버그를 재현·수정하고 P1 화면에서 반복 검증한다.
5. P1이 드래그 선택 제스처를 제공하고 P2가 다각형 ROI 탐지를 연결한다.
6. P2가 인물 포즈 가이드를 구현하고 P1이 점·막대 표현을 완성한다.
7. CAMP-2에 생성형 구도 복구 workflow를 준비한 뒤 P1의 AI 보정 화면과 통합한다.

## 7. P1 전달 메모

이번 요청의 핵심은 카메라 화면에서 기능을 모두 펼쳐놓는 방식에서 벗어나, 실제 카메라처럼
프리뷰를 중심에 두고 필터와 프레임을 필요할 때만 꺼내 쓰는 구조로 바꾸는 것이다.
프레임 선택은 P2 기능이면서 P1 화면 연결이 반드시 필요한 공통 항목이므로 누락하지 않는다.
세부 시각 표현은 SNOW·갤럭시 카메라의 사용성을 참고해 P1 판단으로 완성하되, 감도 브랜드와
시각 오버레이 전용 원칙은 유지해 주기 바람.

## 8. P2 구현 전달 상태 (2026-07-29)

P1 화면 연결 전까지 P2가 제공한 계약은 다음과 같다.

- 풀블리드 좌표: `PreviewGeometry`가 CameraX `FILL_CENTER`, 회전, 전면 카메라 반전,
  safe inset을 하나의 좌표계로 변환한다.
- 프레임 선택: `SceneGuideSessionController.availableManualLayouts`에 12종 프레임과
  썸네일용 슬롯 벡터가 제공된다. 기존 9개 ID는 호환 별칭으로 유지된다.
- 영역 선택: P1이 프리뷰 픽셀 좌표의 닫힌 경로를
  `rescanInPolygon(points, geometry)`에 전달한다. 면적 2~80%와 객체 중심 또는 박스 35%
  겹침 조건은 P2가 검증한다. 취소는 `cancelPolygonSearch()`를 호출한다.
- 포즈: `FixedLayoutTemplate.poseGuide`에 전신 정면·전신 비대칭·상반신·앉은 자세의
  정규화 점·막대가 전달된다. P1은 현재 관절 추적선을 그리지 말고 이 고정 목표만 렌더링한다.
- 내 감도: `ResultFilterStateHolder.state`를 결과 화면의 단일 필터 상태로 구독한다.
  `select()`, `renderStarted()`, `renderSucceeded()`, `renderFailed()`는 목록을 재생성하지 않는다.
  기존 화면 내부의 임시 필터 목록을 함께 소유하지 않는다.
- AI 보정: rescue 응답 v2의 `capabilities`가 참인 작업만 노출한다. Android의
  `RescueOperation.VIEWPOINT`·`RELIGHT`는 기존 submit/poll/download 계약을 그대로 사용한다.

현재 실제 GPU 상태는 다음과 같다.

- LaMa 객체 삭제: 기존 운영 경로 유지.
- IC-Light 재조명: CAMP-2 공식 모델 CUDA smoke와 공개 API edit-job `done` 확인.
- FLUX.1 Fill: gated 모델 접근 토큰이 없어 비활성.
- ViewCrafter: 공식 코드·격리 서비스 계약은 배치했으며 체크포인트·런타임 설치 검증 중.

따라서 P1은 준비되지 않은 기능을 고정 버튼으로 노출하지 말고 서버 capability를 기준으로
구성해야 한다. P1 소유 Compose 파일은 이 P2 작업에서 직접 수정하지 않았다.
