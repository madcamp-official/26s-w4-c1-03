# P2 → P1 통합 요청 — 장면 인식형 고정 레이아웃

> 기준: `AGENTS.md` D2·D3·D12~D17. 이 문서는 P1이 카메라 화면에 연결할 UI·상태 계약만 다룬다.

## 1. 현재 P2 제공 범위

- 온디바이스 객체·얼굴 감지와 최근 5프레임 중 3프레임 안정화
- 라벨이 없어도 일반 물체 슬롯을 만드는 자동 레이아웃
- 최대 4개 슬롯, 자동 확정 뒤 고정, 스타일별 크기·여백 변환
- 수동 고정 레이아웃 9종, 재탐색, 세션 종료 시 초기화 API
- `SceneGuideState`의 고정 레이아웃 템플릿과 `GuideLayoutState`

P2는 카메라 화면의 위치·버튼·바텀시트·색상·타이포그래피를 수정하지 않는다.

## 2. P1이 연결할 API

`SceneGuideSessionController`를 카메라 세션마다 하나 생성한다.

```kotlin
val sceneGuideSession = SceneGuideSessionController()

val state = sceneGuideSession.updateScene(
    detection = detectionResult,
    style = activeStyleTarget,
    signals = sceneSignals,
)
```

- `detectionResult`는 기존 `SceneDetector`의 결과를 그대로 전달한다.
- `state.layoutGuide.fixedLayout`을 기존 `OverlayData.layoutGuide`에 전달한다.
- `layoutState`는 `Searching` 또는 `Fixed(template, AUTO|MANUAL)`이다.
- 기존 `CameraViewModel`의 `SceneGuideCoordinator` 직접 호출은 이 컨트롤러 경로로 통일한다.

## 3. P1 UI 이벤트 계약

| 사용자 동작 | 호출 | 결과 |
|---|---|---|
| 카메라 첫 진입 | 기본 상태 유지 | `Searching`에서 자동 분석 시작 |
| 우측 상단 레이아웃 버튼 | P1이 목록 표시 | 자동·수동 레이아웃 선택 진입 |
| 수동 레이아웃 선택 | `selectManualLayout(templateId, activeStyleTarget)` | 즉시 `MANUAL / Fixed`로 교체 |
| 자동으로 돌아가기·재탐색 | `rescan()` | 현재 고정 해제 후 `Searching`으로 복귀 |
| 스타일 변경 | `updateStyle(activeStyleTarget)` | 고정된 레이아웃의 크기·간격·중심만 갱신 |
| 갤러리 이동·앱 종료·카메라 이탈 | `endSession()` | 선택을 폐기하고 다음 진입은 자동 탐색 |

수동 목록은 `availableManualLayouts`를 사용한다. 현재 9종은 인물, 카페 테이블, 음료 2개, 음료 3개, 정물, 물체 1~4개다.

## 4. 렌더링 규칙

- `Searching`: 작은 비언어 로딩 표시만 보여준다. 레이아웃이 없어도 셔터는 항상 동작한다.
- `Fixed`: 템플릿의 모든 슬롯을 동일한 흰색·반투명 스타일로 그린다.
- 슬롯의 채움·비움, 일치도, 신뢰도, 색상 전환을 사용자에게 표시하지 않는다.
- 객체 외곽선·박스를 프레임마다 따라 그리지 않는다. 최초 확정 템플릿은 재탐색 전까지 고정한다.
- `LayoutGuidePrompt` 텍스트(`피사체를 화면에 보여주세요` 등)는 제품 경로에서 렌더링하지 않는다.
- 수평선 표시는 기존 계약대로 유지한다.

## 5. 현재 코드에서 P1이 교체할 부분

- `CameraViewModel`의 `SceneGuideCoordinator` 직접 호출을 `SceneGuideSessionController.updateScene(detection, style, signals)` 호출로 교체한다.
- `CameraOverlay`의 `SlotMatchStatus`별 색상 분기를 제거하고, 고정 슬롯을 균일한 흰색으로 렌더링한다.
- `CameraOverlay`의 `LayoutGuidePrompt` 텍스트 렌더링을 제품 경로에서 제거한다.
- 레이아웃 버튼·수동 목록·재탐색 UI의 구체적 디자인은 P1이 결정한다.

## 6. 인수 기준

1. 물체가 안정화되기 전에는 작은 로딩만 보이고, 확정 전 임의 슬롯은 보이지 않는다.
2. 안정화된 객체 1~4개 또는 얼굴+객체에서 자동 레이아웃이 한 번 확정된다.
3. 확정 뒤 카메라·객체가 움직여도 슬롯 위치·개수는 바뀌지 않는다.
4. 수동 레이아웃 선택과 재탐색이 즉시 동작한다.
5. 카메라를 벗어난 뒤 재진입하면 항상 자동 탐색으로 시작한다.
6. 슬롯 상태·문구·점수·자동 촬영은 노출되지 않는다.

## 7. P2 품질 한계와 후속

현재 일반 슬롯은 객체 이름을 확정하는 기능이 아니라, 안정적인 객체 박스의 개수·위치·배치를 바탕으로 한 촬영 보조다. 붙은 물체가 하나의 박스로 검출되면 하나의 슬롯으로 처리한다. 실제 물체별 외곽선 품질과 사진 기법 기반 세부 구도는 P1 통합 후 실기기 품질 작업으로 진행한다.
