# 감도 (GAMDO)

> 내 취향을 아는 카메라. 구도를 잡아주고, 내 감성대로 보정하고, 망친 사진은 AI로 살린다.

몰입캠프 26s W4 C1-03 프로젝트. Android 네이티브 카메라 앱과 이를 지원하는 GPU 서버·웹 카메라로 이루어져 있다.

---

## 감도가 뭐예요?

사진을 잘 찍고 싶지만 구도를 어떻게 잡아야 할지, 보정을 어떻게 해야 내 느낌이 나는지 모르는 사람을 위한 카메라 앱이다.

1. **처음 켜면** 마음에 드는 사진 카드를 고른다. 그걸로 앱이 나의 **감도**(취향 프로필)를 만든다.
2. **카메라를 켜면** 화면 위에 반투명 가이드가 뜬다. 피사체를 어디에 두면 좋을지 앱이 장면을 보고 제안한다. 텍스트 지시나 점수는 없다 — 가이드는 눈으로 보고 맞추는 시각 표식뿐이고, 셔터는 언제나 사용자가 직접 누른다.
3. **찍은 사진은** 내 감도의 색감으로 보정해서 새 파일로 저장한다. 원본은 절대 덮어쓰지 않는다.
4. **좋아하는 사진 한 장으로** 나만의 필터(내 감도)를 만들 수도 있다. 서버가 그 사진의 구도·색감을 분석해 촬영 가이드와 보정 색감에 반영한다.
5. **망친 사진은** AI로 살린다. 방해물 지우기, 여백 넓히기, 빛 고치기, 보는 위치 바꾸기 — 원하는 작업을 고르고 실행을 눌러야만 서버 GPU가 돈다.
6. **친구에게 찍어달라고 할 때는** QR을 보여준다. 친구는 앱 설치 없이 웹 카메라를 열고, 내 화면에 있던 것과 같은 구도 가이드 위에서 찍어준다. 사진은 내 앨범으로 들어온다.

## 화면 흐름

```text
앱 최초 실행
→ 취향 카드로 기본 감도 생성
→ 카메라: 자동 구도 탐색 또는 수동 프레임 선택
→ 직접 촬영
→ 앨범에서 사진 선택
→ 현재 감도 / 시스템 필터로 로컬 보정 → 새 파일 저장
→ (선택) 사진 한 장으로 내 감도 만들기
→ (선택) AI로 사진 살리기 → 후보 비교 → 저장
→ (선택) QR로 친구에게 '나 찍어줘'
```

## 주요 기능

### 카메라 구도 가이드 (온디바이스)

- 카메라가 장면을 기기 안에서 분석해(EfficientDet, MediaPipe) 주요 피사체 1~4개를 찾고, 사진 구도 원칙에 맞는 **고정 가이드**를 그린다. 고정된 가이드는 피사체를 따라다니지 않는다 — 사용자가 카메라를 움직여 가이드에 맞춘다.
- **상황 칩**: 인물 / 배경 강조 인물 / 카페·음식 / 여행·풍경 / 정물·소품. 칩을 고르면 그 상황에 맞는 구도만 아래 목록에 남는다.
- **수동 프레임**: 자동 인식과 무관하게 원하는 구도를 직접 고른다. 전신·상반신·앉은 인물 같은 인물 프레임과 물체 1~4개 배치 프레임을 제공한다.
- **영역 선택(올가미)**: 연필 버튼을 켜고 화면에서 물체들을 감싸 그리면 그 영역 안에서만 다시 탐색한다.
- **탭 재탐색**: 화면을 탭하면 그 주변으로 장면을 다시 찾는다.
- 라이브 카메라 화면은 **서버로 전송하지 않는다**. 모든 실시간 분석은 기기 안에서 끝난다.

### 필터와 내 감도

- 시스템 감도 6종: Clean Social, Candid Feed, Bright Review, Soft Film, Casual Portrait, Night Street.
- **내 감도**: 좋아하는 사진 한 장을 고르고 동의하면 서버가 구도·팔레트·명암을 분석한다. 적용 범위(구도와 색감 / 구도만 / 색감만)를 고를 수 있다.
- 내 감도가 켜져 있으면 참조 사진을 프리뷰 위에 반투명으로 겹쳐 구도를 참고할 수 있다(투명도 슬라이더 제공). 업로드 시 위치 정보(EXIF/GPS)는 자동 제거된다.
- 프리뷰 색감은 GL(OpenGL) 파이프라인이 실시간으로 입힌다. GPU가 지원하지 않는 기기에서는 색 없이 프리뷰가 계속 동작한다.

### 로컬 보정과 앨범

- 앱 촬영본과 기기 사진이 한 앨범 그리드에 시간순으로 섞여 보인다.
- 보정은 전부 비파괴 — 밝기·따뜻함·대비 조절, 필터 선택 후 **새 파일로** 저장한다.
- 앱이 찍은 사진은 촬영 당시 환경(기울기·역광 등)을 기록해 보정 출발점과 진단 칩에 활용한다.

### AI로 사진 살리기

앨범 사진에서 `AI로 보정`에 들어가면 사진 진단 후 작업을 제안한다. 실행 버튼을 눌러야만 서버 작업이 시작된다.

| 작업             | 하는 일                       | 모델         |
| ---------------- | ----------------------------- | ------------ |
| 내 감도로 정리   | 서버 없이 즉시 로컬 색감 보정 | (온디바이스) |
| 방해 요소 지우기 | 마스크로 지정한 물체 제거     | LaMa         |
| 여백/화각 넓히기 | 사진 바깥을 생성해 확장       | FLUX.1 Fill  |
| 빛 균형 맞추기   | 역광·조명 개선                | IC-Light     |
| 보는 위치 바꾸기 | 시점을 약하게 재해석          | ViewCrafter  |

생성 결과는 원본·기본 보정과 나란히 비교한 뒤 골라서 저장한다. 실패해도 원본과 로컬 보정은 항상 남는다.

### QR '나 찍어줘'

- 카메라의 공유 버튼 → 현재 구도 가이드로 QR 생성 (세션 60분, 최대 5장).
- 친구는 QR을 열어 브라우저 카메라로 찍는다. 앱 설치·로그인 불필요. 웹에는 같은 고정 가이드만 그려지고 AI 분석은 돌지 않는다.
- 도착한 사진을 받으면 전부 내 앨범에 들어오고, 첫 장은 바로 보정 화면으로 열린다.

## 개인정보 원칙

- **로그인 없음.** 프로필·선호·촬영 기록은 전부 기기 안 Room DB에 저장된다.
- **라이브 카메라 프레임은 서버로 보내지 않는다.** 서버는 사용자가 사진을 고르고 명시적으로 실행한 경우(내 감도 분석, AI 살리기)에만 사용된다.
- 업로드되는 사진은 위치 정보를 제거한 뒤 전송된다.

## 빌드하고 실행하기

### 요구 사항

- JDK 17 — Android Studio 동봉 JBR 권장 (`JAVA_HOME`을 `<Android Studio>/jbr`로)
- Android SDK (API 34 기준), 실기기 권장 — 카메라 기능이 중심이라 에뮬레이터로는 절반만 보인다

### Android 앱

```bash
# 개발용 (디버그 HUD·탐지 로그·지연 계측 포함)
./gradlew :app:assembleDebug

# 시연용 — 필수!
./gradlew :app:assembleDemo
```

빌드 변형이 **두 개**인 이유: ART는 디버그 가능한 앱의 JIT 최적화를 제한한다. 보정 화면의 필터 연산이 그 페널티를 정통으로 맞아서, 같은 코드가 debug에서는 필터 탭당 ~1초, demo에서는 ~55ms다. **사람 앞에서 돌리는 빌드는 반드시 `demo`**(`com.gamdo.app.demo`)를 쓴다. debug(`com.gamdo.app.debug`)와 나란히 설치되지만, 카메라를 쓰는 앱을 **동시에 두 개 띄우지는 말 것**(카메라·GPU 자원 경합).

```bash
# 단위 테스트 (JVM, 기기 불필요)
./gradlew :app:testDebugUnitTest
```

### 서버 (선택)

내 감도 분석·AI 살리기·QR 기능만 서버가 필요하다. 카메라·가이드·로컬 보정은 서버 없이 전부 동작한다.

```bash
cd gamdo-server
pip install -r requirements.txt        # GPU 모델까지 쓰려면 requirements-gpu.txt
uvicorn app.main:app --reload
```

### QR 웹 카메라 (선택)

```bash
cd gamdo-web
npm install
npm run dev
```
